## Prime Intellect が prime-agent を公開：コンテキストを変数、ツールを関数呼び出しとして扱う「RLM」エージェント

- **概要**：Prime Intellect が prime-agent をオープンソース化（1 日で +2,293、累計 6.5k スター）——コーディングと長期自律タスク向けのオープンソースエージェントで、RLM（Recursive Language Model、再帰言語モデル）という発想を核とする：永続化された Python REPL（IPython を内蔵モデルツールとして使用）の中で、コンテキストを変数として、ツールをプログラム可能な関数呼び出しとして扱う（並列サブエージェントを派生させる `rlm(...)` を含む）——通常の対話型ツール呼び出しループではない。`/refine` 能力を搭載——タスクの軌跡を復盤し、根拠に基づく更新を補助的な harness 状態（記憶、skills、サブエージェント仕様）に書き戻し、セッションを跨いで永続化する「自己改善」を実現する。長時間タスク向けには、デーモンによる継続性（ターミナルが切断してもセッションは失われない）、ターンを跨ぐ永続目標、定期的に再開させるハートビート、スケジュール、トークン/時間予算を設定可能な有界自律モードを備える。アーキテクチャはデーモン・ワーカー・カーネルの 3 層で永続状態の境界を持つ。
- **なぜ重要か**：「コーディングエージェントはどうあるべきか」という問いへの構造的に異なる答えである——チャットループの上にツール呼び出しを積み上げるのではなく、エージェントのランタイム全体を永続的なプログラミング環境としてモデル化し、エージェントの「思考」はその環境の中でコードを書き、変数を読み書きすること自体になる。「軌跡を復盤して harness 自身の状態を更新する」という `/refine` の自己改善メカニズムは、loopx の外部状態カーネルや Matt Pocock skills の経験抽出と同じ「実行に再利用可能な蓄積を残す」という発想の別レイヤーでの表れであり、prime-agent はこの循環を外部ツールではなくエージェント自身の内蔵能力として作り込んでいる点が異なる。
- **分類**：Agent
- **関連 Topic**：[coding-agents](/ja/topics/coding-agents) ・ [deep-agents](/ja/topics/deep-agents)
- **出典**：https://github.com/PrimeIntellect-ai/prime-agent

## Google が公式に skills を公開：Google 製品ラインの Agent Skill 集

- **概要**：google/skills（1 日で +327、累計 1.62 万スター）——Google 公式リポジトリで、自社の製品と技術をカバーする Agent Skills を提供する：クラウド基盤（GKE、ストレージ、ネットワーキング）、AI/ML（Agent Platform 管理、Gemini API、モデルのチューニングとデプロイ）、データ分析（BigQuery、AlloyDB、Spanner、Bigtable）、開発者ツール（gcloud CLI、Firebase）、セキュリティ（GKE セキュリティ、検知エンジニアリング）、Well-Architected Framework の 6 本柱にわたるベストプラクティス、広告（Google Ads API、Mobile Ads SDK）、そして Cloud Run/Logging/Monitoring など。
- **なぜ重要か**：2 人の著名な独立エンジニアの高スター skill パックに続き、自社製品ラインの skill 集を公式にメンテナンスする初のハイパースケーラーが現れた——「skill は製品ドキュメントの実行可能版である」という位置づけがプラットフォームベンダーに正式に採用され始めたサインである。コミュニティが GKE や BigQuery 向けの skill を書くのを待つのではなく、ベンダー自身が権威あるバージョンをメンテナンスする——公式ドキュメントと同期し続けるという信頼性の優位性を自然に備えている。GCP スタックを使うチームにとっては、現時点で入手できる最も網羅的な公式 Google Cloud skill ソースである。
- **分類**：Agent
- **関連 Topic**：[agent-skills](/ja/topics/agent-skills)
- **出典**：https://github.com/google/skills
