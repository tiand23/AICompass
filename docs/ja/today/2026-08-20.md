# 2026-08-20

## Claude Python SDK が v1.0 に：httpx から httpx2 へ移行、長期廃止予定だったインターフェースを複数削除

- **概要**：Anthropic が Claude Python SDK v1.0 をリリース：HTTP 層を `httpx` から保守された API 互換フォーク `httpx2` へ移行（tracing/mocking のために httpx にパッチを当てるライブラリは `httpx2.alias_httpx()` の呼び出しが必要）；Python 3.10+ が必須；legacy Text Completions API、Messages メソッドの `temperature`/`top_p`/`top_k`、tool runner のクライアント側 `compaction_control` など長期間廃止予定だったインターフェースを削除；非同期クライアントの `.with_raw_response` の結果は `await response.parse()` が必要に；`AnthropicBedrock` はリージョン未設定時に `us-east-1` へのデフォルトではなくエラーを返すように変更。完全な移行ガイドが提供されている。
- **なぜ重要か**：典型的な「負債整理」型のメジャーリリース——削除された項目はいずれも長らく廃止予定だったもので、最新の使い方に従っているユーザーはほとんど影響を受けないが、旧バージョンに留まっている、httpx にパッチを当てている、あるいはリージョンを設定していない統合先は移行ガイドに沿って一つずつ確認する必要があり、実質的な破壊的変更となる（詳細は [claude-models](/ja/topics/claude-models)）。
- **分類**：Agent
- **関連 Topic**：[claude-models](/ja/topics/claude-models)
- **出典**：https://platform.claude.com/docs/en/release-notes/overview

## LangSmith が Preview Builds 公開ベータをローンチ：PR ごとに Agent プレビューデプロイを自動生成

- **概要**：LangSmith Preview Builds 公開ベータ：PR を開くと本番環境に紐づいた隔離済みのプレビューデプロイが自動生成され、新しいコミットで自動再構築・同期される——チーム（製品担当、領域専門家、QA などの非エンジニアの役割も含む）に、PR ごとに直接アクセスしてテストできる「PR 専用の成果物」を提供し、PR のたびにフル本番デプロイを立てる必要がなくなる。「すべての PR」または「ラベル付きのみ」のトリガーに対応；プレビューは親デプロイのシークレットを継承し、アイドル TTL と最大同時プレビュー数を設定可能。GitHub 統合を使う LangSmith Cloud のデプロイでのみ利用可能で、ベータ期間中の価格は非公開。
- **なぜ重要か**：Web 開発で成熟した「CI/CD プレビュー環境」という実践を Agent デプロイに体系的に持ち込むものだ——これまで Agent の変更はローカルでテストするか本番で直接検証するかのどちらかだったが、その中間の協働レビューが可能な段階が生まれた；また非エンジニアの役割を「直接クリックしてテストできる」レビューの輪に組み込む（詳細は [enterprise-ai-agents](/ja/topics/enterprise-ai-agents)）。
- **分類**：Agent
- **関連 Topic**：[enterprise-ai-agents](/ja/topics/enterprise-ai-agents)
- **出典**：https://www.langchain.com/blog/langsmith-preview-builds-test-agent-changes-before-production

## LiquidAI が LFM2.5-DSpark を発表：投機的デコーディング用ドラフトモデルで推論を最大 3.18 倍高速化

- **概要**：Liquid AI が LFM2.5-DSpark を発表——LFM2.5 シリーズ（2.6B/1.2B-Instruct/8B-A1B）向けの投機的デコーディング用ドラフトモデル（約 3 億パラメータ）で、DFlash 式の並列バックボーン、軽量な逐次ヘッド（隣接 token のマルコフ依存関係をモデル化し採択率を高める）、信頼度スケジュール検証器（検証コストが利益を上回る場合に低信頼度の接尾辞を刈り込む）を組み合わせる。H100 上で平均 2.1〜2.67 倍の高速化（MATH500 でピーク 3.18 倍）、M4 Max MacBook 上のオンデバイスで 1.18〜2.54 倍の高速化、関数呼び出しのレイテンシを平均 57% 削減；出力は貪欲デコーディングのベースラインと token 単位で一致し、品質は劣化しない。llama.cpp（Metal カーネル）と SGLang に既に対応。
- **なぜ重要か**：同じバッチの QAD（量子化路線、08-19 に収録）と補完関係にある——一方はより精密な量子化で精度を保ち、もう一方は目標モデルの挙動をより理解したドラフトモデルで精度を保つ。2 つの路線を合わせると「エッジモデルを品質を落とさず高速化する」という課題の主要な解法をカバーする（詳細は [model-efficiency](/ja/topics/model-efficiency)）。
- **分類**：Models
- **関連 Topic**：[model-efficiency](/ja/topics/model-efficiency)
- **出典**：https://huggingface.co/blog/LiquidAI/lfm25-dspark
