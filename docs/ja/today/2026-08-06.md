## Cloudflare が computer を公開：エージェント向けのプログラム可能な「コンピュータ」

- **概要**：Cloudflare が computer をオープンソース化（1 日で +891、累計 2,900 スター）——Durable Object 内で動く仮想ファイルシステム（状態は SQLite に保存）に、3 種類の差し替え可能な実行バックエンドを組み合わせる：Container（状態を実際の FUSE マウントに投影し、完全な Linux ユーザーランドとネットワークアクセスを提供）、Isolate Shell（Dynamic Worker 内で just-bash を実行し、Workers RPC 経由でワークスペースにアクセス）、Isolate JavaScript（新規の Dynamic Worker で ES モジュールを実行）。統一エントリポイントは `workspace.runtime.exec()`、ワークスペースはバックエンドなしでも単独動作可能。現時点では明確に「プレビューのみ、本番利用には未対応」。
- **なぜ重要か**：E2B や Daytona が切り開いた「Agent サンドボックス・アズ・ア・サービス」というアイデアの、クラウドベンダー自身による実装——しかも「ファイルシステム状態」と「実行バックエンド」を切り離し、独立した 2 つの層にしている。同じワークスペース状態を、実コンテナ・隔離シェル・純粋な JS サンドボックスの間で必要に応じて切り替えられ、1 種類の隔離強度に縛られない。アーキテクチャ上の示唆は、Agent 実行環境の「ストレージ層」と「隔離層」は本来独立して差し替え可能な部品であるべきで、多くのサンドボックス製品のように一体化して固定すべきではない、という点。
- **分類**：Agent
- **関連 Topic**：[agent-sandboxes](/ja/topics/agent-sandboxes)
- **出典**：https://github.com/cloudflare/computer

## loopx が登場：長期稼働する Agent チームの「状態カーネル」

- **概要**：huangruiteng/loopx（1 日で +326、累計 2.1k スター）——Agent のランタイム自体を置き換えるのではなく、Codex/Claude Code/Cursor など任意の Agent の上に「Agent ネイティブなカンバン」というローカルなコントロールプレーンを追加する：複数ターン・複数セッションを生き延びる永続目標（Durable Goals）、認領・引き継ぎ可能な実行可能タスク（Executable Todos）、予算に基づいて継続/人への相談/待機/停止を判断するクォータ意識スケジューリング、意思決定と検証を保持する証跡ログ、型付きで検証可能な引き継ぎ（Verifiable Handoffs）を提供する。
- **なぜ重要か**：長期に及ぶマルチ Agent 協調の本当のギャップを的確に突いている——チャット UI は「目標がずれる、責任が転手する、証拠が陳腐化する、コストがセッションを跨いで静かに積み上がる」といった状態を扱うのに構造的に向いていない。loopx は別の Agent フレームワークではなく、Agent 非依存の外部状態管理層を作っている。「ランタイムの外に状態カーネルを一層立てる」というこの設計方針は、AIDD の Staging Area + 証拠チェーンのアプローチと並べて見る価値がある——どちらも本質は「自律実行に監査可能な永続状態の層を足す」ことである。
- **分類**：Agent
- **関連 Topic**：[deep-agents](/ja/topics/deep-agents)
- **出典**：https://github.com/huangruiteng/loopx

## Addy Osmani が agent-skills を公開：プロフェッショナルなエンジニアリング規律を 24 の Skill に封装

- **概要**：Addy Osmani（元 Google Chrome チーム、『Learning JavaScript Design Patterns』著者）が agent-skills を公開（1 日で +226、累計 8.2 万スター）——開発ライフサイクル全体（Define/Plan/Build/Verify/Review/Ship）をカバーする 24 の skill モジュールで構成され、各 skill にはステップバイステップのワークフロー、検証要件、そして「Agent が手順を飛ばすために使いそうな言い訳」を明示的に列挙し 1 つずつ封じる表が付属する。8 つのスラッシュコマンド（`/spec`、`/plan`、`/build`、`/test`、`/review`、`/webperf`、`/code-simplify`、`/ship`）と 4 つの専門家ペルソナ（コードレビュアー、テストエンジニア、セキュリティ監査、パフォーマンス監査）を備え、70 以上のコーディング Agent クライアントへのインストールに対応。
- **なぜ重要か**：8.2 万スターは現時点で skill エコシステム単体で最も高い熱量であり、匿名リポジトリではなく著名なエンジニアの手によるもの——ある意味で「skill コンテンツの品質」に初めて広く認知された高水準の基準点ができた。「Agent が手順を飛ばすために使う言い訳を明示的に列挙し反論する」という設計の細部は、skill の書き方が「Agent に何をすべきか教える」から「Agent の手抜きを防ぐ」へと深化していることを示す——skill が工学規律の担い手として成熟した顕著な一歩。
- **分類**：Agent
- **関連 Topic**：[agent-skills](/ja/topics/agent-skills)
- **出典**：https://github.com/addyosmani/agent-skills
