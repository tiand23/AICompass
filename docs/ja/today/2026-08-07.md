## Matt Pocock が skills を公開：個人の `.agents` ディレクトリから精製した工学規律

- **概要**：著名な TypeScript 教育者 Matt Pocock が skills を公開（1 日で +1,873、累計約 20.7 万スター）——長年蓄積してきた自身の個人 `.agents` ディレクトリから抽出・精製したもので、面談式プランニング（`grill-me`、`grill-with-docs`）、テスト駆動開発ワークフロー、コードレビューとデバッグの規律、アーキテクチャ評価、ドメインモデリングと共有語彙の構築、チケットのトリアージなどをカバーする。狙うのは AI 支援開発でよくある失敗パターン——ユーザーの意図と成果物のズレ、Agent の冗長な回答、コード品質とアーキテクチャの劣化——への対処。インストーラー（`npx skills@latest add mattpocock/skills`）を提供し、購読型の自動更新か、カスタマイズ可能な fork コピーかを選べる。
- **なぜ重要か**：Addy Osmani の agent-skills から 1 日後に、また別の著名な独立エンジニアが個人の経験を高スターの skill パックへ精製した——「個人の `.agents` ディレクトリに蓄積した経験を公開する」ことが再現可能なパターンになりつつある。「面談式プランニング」（着手前にまず反問して意図を確認する）という設計は、Agent 協働で最も一般的かつ定量化しにくい失敗パターンである意図-成果物のズレに直接対応するもので、単なる手順系 skill よりも「コミュニケーションの整合」というより難しい問題に一歩踏み込んでいる。

## code-review-graph が登場：Tree-sitter コードグラフで AI ツールに「血統分析」をさせトークンを節約

- **概要**：tirth8205/code-review-graph（1 日で +237、累計 2.9 万スター）——Tree-sitter でコードベースの関数・クラス・import・呼び出し関係を有向グラフに解析し、ローカルの SQLite（`.code-review-graph/` ディレクトリ）に保存する。コード変更時は影響範囲分析（blast-radius）を行い、影響を受ける呼び出し元・依存先・テストを追跡する。AI ツールはファイルツリー全体を読む代わりに、30 個の MCP ツール経由でこのグラフを問い合わせる。実測：Flask のコードベースをナイーブにレビューすると 143,594 トークンかかるが、グラフを使えばわずか 2,196 トークン——**71 倍**の削減。6 つの実リポジトリでの質問あたり中央値は約 **65 倍**の節約。増分更新（3,000 ファイルのプロジェクトで再インデックス約 2.5 秒）、40 以上の言語対応、リスクスコア付き PR レビューの GitHub Action、任意のベクトル意味検索、Leiden アルゴリズムによるコミュニティ検出にも対応。
- **なぜ重要か**：「AI ツール向けにコード構造グラフを構築してトークンを節約する」という発想の、具体的かつデータに裏付けられた実装——本質的には、文書解析の「空間的位置特定」や動画編集の「転写による代理」で既に見たのと同じパターンの 3 度目の再来である：高次元の生情報（コードベース全体のテキスト）を構造化された低次元の代理表現（呼び出しグラフ）に圧縮し、その代理表現の上で主に推論し、真にソースレベルの詳細が必要な箇所だけ局所的に展開する。グラフの問い合わせインターフェースとしての MCP も、「テキストダンプではなくプロトコルで構造化知識を公開する」という実践のもう一つの実例である。
- **分類**：Coding
- **関連 Topic**：[ai-code-review](/ja/topics/ai-code-review) ・ [coding-agents](/ja/topics/coding-agents)
- **出典**：https://github.com/tirth8205/code-review-graph
