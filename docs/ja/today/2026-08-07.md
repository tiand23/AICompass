## Matt Pocock が skills を公開：個人の `.agents` ディレクトリから精製した工学規律

- **概要**：著名な TypeScript 教育者 Matt Pocock が skills を公開（1 日で +1,873、累計約 20.7 万スター）——長年蓄積してきた自身の個人 `.agents` ディレクトリから抽出・精製したもので、面談式プランニング（`grill-me`、`grill-with-docs`）、テスト駆動開発ワークフロー、コードレビューとデバッグの規律、アーキテクチャ評価、ドメインモデリングと共有語彙の構築、チケットのトリアージなどをカバーする。狙うのは AI 支援開発でよくある失敗パターン——ユーザーの意図と成果物のズレ、Agent の冗長な回答、コード品質とアーキテクチャの劣化——への対処。インストーラー（`npx skills@latest add mattpocock/skills`）を提供し、購読型の自動更新か、カスタマイズ可能な fork コピーかを選べる。
- **なぜ重要か**：Addy Osmani の agent-skills から 1 日後に、また別の著名な独立エンジニアが個人の経験を高スターの skill パックへ精製した——「個人の `.agents` ディレクトリに蓄積した経験を公開する」ことが再現可能なパターンになりつつある。「面談式プランニング」（着手前にまず反問して意図を確認する）という設計は、Agent 協働で最も一般的かつ定量化しにくい失敗パターンである意図-成果物のズレに直接対応するもので、単なる手順系 skill よりも「コミュニケーションの整合」というより難しい問題に一歩踏み込んでいる。

## code-review-graph が登場：Tree-sitter コードグラフで AI ツールに「血統分析」をさせトークンを節約

- **概要**：tirth8205/code-review-graph（1 日で +237、累計 2.9 万スター）——Tree-sitter でコードベースの関数・クラス・import・呼び出し関係を有向グラフに解析し、ローカルの SQLite（`.code-review-graph/` ディレクトリ）に保存する。コード変更時は影響範囲分析（blast-radius）を行い、影響を受ける呼び出し元・依存先・テストを追跡する。AI ツールはファイルツリー全体を読む代わりに、30 個の MCP ツール経由でこのグラフを問い合わせる。実測：Flask のコードベースをナイーブにレビューすると 143,594 トークンかかるが、グラフを使えばわずか 2,196 トークン——**71 倍**の削減。6 つの実リポジトリでの質問あたり中央値は約 **65 倍**の節約。増分更新（3,000 ファイルのプロジェクトで再インデックス約 2.5 秒）、40 以上の言語対応、リスクスコア付き PR レビューの GitHub Action、任意のベクトル意味検索、Leiden アルゴリズムによるコミュニティ検出にも対応。
- **なぜ重要か**：「AI ツール向けにコード構造グラフを構築してトークンを節約する」という発想の、具体的かつデータに裏付けられた実装——本質的には、文書解析の「空間的位置特定」や動画編集の「転写による代理」で既に見たのと同じパターンの 3 度目の再来である：高次元の生情報（コードベース全体のテキスト）を構造化された低次元の代理表現（呼び出しグラフ）に圧縮し、その代理表現の上で主に推論し、真にソースレベルの詳細が必要な箇所だけ局所的に展開する。グラフの問い合わせインターフェースとしての MCP も、「テキストダンプではなくプロトコルで構造化知識を公開する」という実践のもう一つの実例である。
- **分類**：Coding
- **関連 Topic**：[ai-code-review](/ja/topics/ai-code-review) ・ [coding-agents](/ja/topics/coding-agents)
- **出典**：https://github.com/tirth8205/code-review-graph

## Claude Managed Agents が企業向け運用機能を一挙 4 件公開：予算上限、アドバイザーモデル、データ所在地、GitHub からの skill 読み込み

- **概要**：Claude Managed Agents が同日 4 つの機能を公開：①セッション予算——セッション支出のハード上限を設定（公開料金表で課金）。上限に達すると `budget_reached` で一時停止し新規モデルリクエストを開始しない。予算の変更・解除で再開する。②アドバイザー——セッションのプライマリスレッドが途中で戦略的助言を求められる、自身と同等以上の能力を持つ「アドバイザー」モデルを設定できる。③`inference_geo`——エージェント単位またはセッション単位でモデル推論の実行地域を指定でき、データ所在地（data residency）のコンプライアンス要件に対応。④skills を接続した GitHub リポジトリから直接読み込み可能に——セッションがリポジトリをマウントすると、ルートの `.claude/skills` 配下の skill がセッション開始時に自動検出され利用可能になる。
- **なぜ重要か**：この 4 つを合わせて見ると、ホスト型エージェントランタイムが「コスト制御 + 判断の信頼性 + コンプライアンス制御 + 能力の着脱可能性」という企業の必須要件一式を完成させたことがわかる。アドバイザーの設計は特に注目に値する——より強いモデルに実行を代替させるのではなく、プライマリスレッドの途中で戦略判断に介入させる「顧問」として位置づけている点は、「高価なモデルにはその中で最も高価な部分（判断力）だけを使わせる」というコスト階層化の新しい実装形態だ。GitHub リポジトリから skill を直接マウントする方式は、skill の更新とコードリポジトリのバージョン管理が同一ソースになり、別途の配布チャネルを維持する必要がなくなる。
- **分類**：Agent
- **関連 Topic**：[cloud-agent-platforms](/ja/topics/cloud-agent-platforms) ・ [agent-skills](/ja/topics/agent-skills)
- **出典**：https://platform.claude.com/docs/en/release-notes/overview

## Anthropic が Fable 5 の生物学分野の誤判定を大幅に縮小：偽陽性を約 85% 削減

- **概要**：Anthropic は Fable 5 の生物学安全性分類器の「憲法」（制限対象と許可対象を区別するルール集）を書き直し、良性用途向けの細かい例外規定を追加、専門家のフィードバックを収集し、更新した学習データで分類器を再学習した——その結果、生物学関連の誤ブロック（fallback）が約 85% 減少し、モデルはより広範な正当な生物学タスクを支援できるようになった。ウイルス学・毒物学・分子設計の 3 分野のリクエストは引き続きブロックされ、能力の低い Opus 5 にルーティングされる。フロンティア生物学研究向けの信頼済みアクセス経路は開発継続中。
- **なぜ重要か**：「デュアルユースの安全ガードレール」が「一律制限」から「精緻な較正」へ移行する具体的な事例——Fable 5 は際立った生物学能力ゆえに発表時は広範な制限を敷いたが、今回の調整は安全チームが実際の利用データを分類器へ本当にフィードバックし続けていることの証左であり、ガードレールを設定したまま放置しているわけではない。生命科学・化学など機微な領域を扱う開発者にとっては、以前誤ブロックされた正当なリクエストを再試行する価値がある。また「規則の精緻化 + データフィードバック」がガードレール精度向上の再現可能な方法論であり、単純な閾値の緩和ではないことも示している。
- **分類**：その他（セキュリティ）

## LangSmith が Managed Deep Agents の公開ベータを発表：Deep Agents のホスト型ランタイム

- **概要**：LangSmith が Managed Deep Agents の公開ベータ（Public Beta）を発表——オープンソースの Deep Agents フレームワークをホスト型サービスに変えるもの：ローカルでは `mda dev` で開発・デバッグし、`mda deploy` で LangSmith ホスト型ランタイムにデプロイする。永続実行（長時間タスクは状態を失わずに一時停止/再試行/再開可能）、ストリーミング進捗と状態永続化、サンドボックス（LangSmith Sandboxes と連携したファイル操作・コード実行の隔離環境）、セッションを跨ぐエージェント単位の永続記憶、ネイティブな Slack/GitHub 接続チャネル、OIDC 対応の ID 認証とユーザー単位のスレッド分離、Harbor フレームワークによる評価統合、LangSmith 全体でのフルトレーシングを提供する。現時点では LangSmith Cloud（米国リージョン）限定、CLI 優先で、料金は未公表。
- **なぜ重要か**：Deep Agents 自体はオープンソースかつモデル非依存でセルフホスト可能なまま残る；Managed 版は永続実行・サンドボックス・記憶・可観測性というこれまで自分で組み立てる必要のあった運用基盤を、すぐ使えるホスト型ランタイムに一括パッケージ化した。本ナレッジベースで繰り返し登場する「プラットフォームが基盤を、事業が能力を供給する」分業モデルのまた一つの実例であり、LangChain エコシステムが「Deep Agents というオープンソースフレームワーク」から「Deep Agents のホスト型ランタイム」へ自然に延伸したものでもある——Claude Managed Agents、Gemini API Managed Agents に続き、「深いエージェントのホスト化」を正式に製品ラインとして打ち出した 3 社目。
- **分類**：Agent
- **関連 Topic**：[deep-agents](/ja/topics/deep-agents) ・ [enterprise-ai-agents](/ja/topics/enterprise-ai-agents) ・ [cloud-agent-platforms](/ja/topics/cloud-agent-platforms)
