## Microsoft が「Agent ファースト・プラットフォーム」アーキテクチャを提唱：ガバナンスと実行環境の分離

- **概要**：Microsoft Foundry が、Agent アプリケーションは従来型アプリとは異なるインフラ上の前提を必要とすると主張する記事を公開——従来型アプリはユーザーのリクエストに応答するが、Agent はループの中で継続的に自律行動する；共有インフラの上で Agent を動かすことはセキュリティと制御のリスクを生む。推奨されるアーキテクチャは、ガバナンス（Microsoft Foundry）と実行環境（Azure Container Apps Sandboxes：秒単位で作成され、作業が終われば消滅するハードウェアレベルで隔離された microVM）を分離し、Agent が限定された権限の下で動作できるようにすることで、監視を維持しつつ影響範囲を限定するというもの。3 つの事例が紹介されている——KPMG は同時に 3 万個を超える Azure Container Apps Sandboxes を稼働；Cognite Atlas AI は数日かかっていた調査を追跡可能な分単位の回答に短縮；南オーストラリアの教育システムは独自のコードインタプリタ状態管理コードを約 5 万行削減した。
- **なぜ重要か**：「Agent に道具の山ではなく自分専用のコンピュータを与える」という考え方（08-11 の monday.com Sidekick 事例）を、ガバナンス面と実行面の分離という明示的なインフラアーキテクチャ原則へと初めて体系化したものであり、3 つの定量化された本番事例がそれを裏付けている。
