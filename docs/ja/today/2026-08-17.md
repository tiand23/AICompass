# 2026-08-17

## Google が Imagen 4 の 3 つの生成エンドポイントを正式終了、Gemini ネイティブ画像モデルへ全面移行

- **概要**：Google は 2026-08-17、Gemini API 側の Imagen 4 の 3 つの生成エンドポイント（`imagen-4.0-generate-001`、`imagen-4.0-fast-generate-001`、`imagen-4.0-ultra-generate-001`）を正式に終了し、呼び出し元に Gemini 3.1 Flash Image への移行を促した；Imagen 4 は既に 2026-03-24 に Vertex AI 側で非推奨化されており、今回は Gemini API 側での最終的な提供終了となる。Google は特に、これがシームレスな置き換えではないと明言している——従来の `generate_images()` メソッドは完全に消滅し、呼び出し元は単にモデル名を変更するのではなく、Gemini ネイティブの画像生成 API に合わせて呼び出し方法を書き直す必要がある。
- **なぜ重要か**：これは「独立した専用モデルラインが汎用の旗艦モデルに統合される」という収斂パターンの、また 1 つの事例だ——OpenAI が以前、独立ブラウザ製品 Atlas を ChatGPT/Codex に統合したのと同様に、Google は独立した画像生成モデルライン Imagen を Gemini のネイティブなマルチモーダル能力に統合しつつある。同じ収斂ロジックが、ベンダーや製品形態を問わず繰り返し現れている：独立した技術スタックと独立したブランドを維持し続けるよりも、能力を旗艦モデルの統一されたイテレーションサイクルに組み込む方を選ぶ、という判断だ。Imagen API を利用しているチームにとって、これは先送りできるモデルアップグレードではなく、明確な期限と破壊的な API 変更を伴う強制的な移行であり、事前の計画とテストが必要だ。
