## OpenAI DevDay 2026：常駐 Agent「Dots」、GPT-6.1 Sol、Pro 500/Ultrafast、ChatGPT Space、Private Intelligence

- **概要**：OpenAI DevDay 2026 で 20 以上の更新を一度に発表。主な内容：**Dots**——24 時間 365 日稼働する Agent で、自分専用のコンピュータとブラウザを持ち、4,000 以上のエコシステムアプリに接続可能、フィードバックから継続的に学習、Astra により駆動され、Pro サブスクリプションに含まれ利用枠を消費しない；**GPT-6.1 Sol**——GPT-6 Sol のアップグレード版で、コーディング/コンピュータ使用/専門的業務における知能が Astra に近づきながら、標準の入出力価格は Astra の 5 分の 1；**Pro 500**——月額 $500 の新ティアで、Plus の 25 倍の利用枠と Ultrafast スピードティアへのアクセスを含む；**Ultrafast**——有料のスピードティアで、Codex では最大 8 倍、API では 6 倍のトークン生成速度向上を謳う；**ChatGPT Space**——Pages（人間と Agent が共同編集する新しいドキュメント形式）、ファイル、プロジェクトのコンテキスト、チームメンバー、AI Agent を 1 つの共有ワークスペースにまとめる；**OpenAI Private Intelligence**——ゼロデータ保持の Private Safety Processing が利用可能になり、機密計算を伴う Private Inference は今秋後半にプレビュー予定。
- **なぜ重要か**：09-03 の GPT-6 Astra 発表から 1 か月以内での OpenAI 最大規模のプラットフォーム更新——Dots は「常駐の自律 Agent」を独立製品ではなくサブスクリプションのデフォルト機能にし、GPT-6.1 Sol は旗艦モデルの能力を主力ティアに引き下げ価格を大幅に下げるという流れ（これまでの Luna/Terra の値下げと同様）を継続し、ChatGPT Space + Pages は「人と Agent の協働ドキュメント」を製品化した——これら 3 つの方向性を合わせると、Agent の自律性、低コストの作業用モデル、協働ドキュメントを 1 つの統合されたワークスペースにまとめる OpenAI のロードマップが見えてくる。

## H Company が Holo4 をオープンソース化：GUI・コード・MCP を自律的に切り替える汎用コンピュータ使用 Agent モデル

- **概要**：H Company が Hugging Face に Holo4 の重みを公開（27B 稠密モデルと 35B-A3B MoE モデルの 2 サイズ、さらに小型の Holotron4 Nano）、H Company 独自の Agentic Task Factory が生成した大規模な環境/タスクデータによる教師あり学習と強化学習で訓練；単一モデルが各ステップでどのインターフェースを使うかを自律的に判断する——画面上でクリック・入力する、自らコードを書いて実行する、または MCP/API ツールを呼び出す。OSWorld 2.0 ベンチマークでは Holo4 27B が 61.7%（Claude Opus 5.5 の 81.8% に対して）、35B-A3B は 30.9% を記録し、旗艦閉源モデルより 1～2 桁少ないパラメータ数とはるかに低いコストでこれを達成している。重みは BF16、FP8、NVFP4、4-bit GGUF の各形式で公開。
- **なぜ重要か**：オープンなコンピュータ使用 Agent モデルが「タスクに応じてどのインターフェースを使うかをモデル自身が自律的に判断する」（GUI 固定でもコード固定でもない）方向へ進化している具体例であり、旗艦閉源モデルとの大きなスコア差をオープンウェイトと低コストデプロイと引き換えにしている——「より小さく安価な専用モデルで垂直領域の能力をカバーする」という効率化の流れを継続している。
- **分類**：Agent

## 研究が ProvenanceGuard を提案：MCP Agent 向けの「出典認識型」事実検証

- **概要**：論文「ProvenanceGuard: Source-Aware Factuality Verification for MCP-Based LLM Agents」は、既存の事実検証手法（RAGAS faithfulness、MiniCheck、AlignScore、SummaC など）が「ある主張が証拠プール全体のどこかで支持されているか」だけを判断し、「出力が引用している具体的な出典が実際にその主張を支持しているか」を判断しない点を指摘する。この「クロスソース混同」という失敗モード（主張は証拠プールのどこかでは真だが、誤った出典に帰属させられている）は、従来の検証手法をすり抜けてしまう。ProvenanceGuard は、安定したツール ID・出典 ID・生の出力を含む MCP のトレース記録を入力とし、回答を原子的な主張に分解し、各主張を対応する出典の証拠にルーティングし、NLI とトークンアラインメントの代理指標で支持度を検証し、「主張されている出典」と「実際にルーティングされた出典」を比較し、主張ごとの判定と全体としての許可/拒否の結論を出力する。
- **なぜ重要か**：MCP によって Agent は複数のツール/データソース呼び出しを一度に組み合わせて回答を組み立てられるようになったが、現在主流の事実検証手法は「引用元が正しいかどうか」を気にしない——この盲点は MCP Agent の普及とともに拡大していく。ProvenanceGuard は「帰属の正しさ」を独立した検証次元として体系化した初めての手法である（詳細は [mcp](/ja/topics/mcp)）。
- **分類**：Evaluation
- **関連Topic**：[mcp](/ja/topics/mcp)・[agent-evaluation](/ja/topics/agent-evaluation)
- **出典**：https://huggingface.co/blog/MultiverseComputingCAI/getting-the-source-right-not-just-the-fact-source
