## LangChain が Orange Business の事例を公開：12 万人の従業員、150 社超の顧客を持つ企業向け Agent プラットフォーム

- **概要**：Orange Business が LangChain/LangSmith を基盤に 3 層構成の企業向け Agent プラットフォーム「Live Intelligence」を構築——Studio（LangSmith Fleet と MCP 対応を含む Agent 開発環境）、Portal（HR・法務・サポートなど業務チーム向けのエンドユーザーインターフェース）、Console（管理とガバナンス）；ガバナンス層には Agent Registry（Agent/prompt のバージョン・ライフサイクル管理）と MCP Registry（M365/CRM/API をカバーする信頼済みツールと企業コネクタの一元カタログ）を含む；評価は 3 層構成（RAG の品質、ツール選択の正確性とプロンプトインジェクション耐性を含む Agent の行動検証、本番環境の監視）；Orange 社内 12 万人の従業員に展開済み、フランス・欧州で 150 社超の顧客が採用、同等のインフラを自社構築するには 12〜18 か月を要したはずだと Orange は述べている。

## LangChain が ScaleDown と Deep Agents の統合を発表：専用小型モデルが長時間セッションのコンテキスト管理を引き継ぐ

- **概要**：LangChain が ScaleDown の「制約付きデコードモデル」（CDM）と Deep Agents の統合を発表——長時程 Agent のコンテキスト管理の課題（履歴が増える中で何を残し、何を要約し、何を圧縮するかを前沿 LLM で判断するのは遅くて高コスト）に対し、汎用の前沿モデルを狭いタスクに特化した専用モデルで置き換える：`ScaledownSummarizationMiddleware` が Deep Agents 組み込みの要約ミドルウェアを置き換え古い対話履歴を圧縮（GPT 系モデルより 41 倍安い）；ツール結果圧縮ミドルウェアが大きなツール出力を Agent に見せる前に関連部分を抽出（実証されたトレースで約 90% のコンテキスト削減）；抽出モード（注文番号やメールアドレスなどの構造化された値を言い換えずに正確にコピー）；分類モード（定義されたカテゴリに対しラベル付けし確信度と理由を付与、Agent の行動ドリフト検知やルーティングに利用可能）。これらの狭タスク専用モデルは前沿モデルより 200 倍速く、467 倍安いと ScaleDown は述べている。
- **なぜ重要か**：「垂直的な場面にフロンティア級の知能は不要」という効率哲学を、長時間セッションのコンテキスト管理という具体的な部分問題に特化させた事例——要約/圧縮/抽出/分類といった構造的・高頻度・低創造性の判断をメインモデルのループから切り出すことは、長時程 Agent の運用コストを削減する直接実装可能なパターンである（詳細は [deep-agents](/ja/topics/deep-agents) ・ [model-efficiency](/ja/topics/model-efficiency)）。
- **分類**：Agent
- **関連Topic**：[deep-agents](/ja/topics/deep-agents)・[model-efficiency](/ja/topics/model-efficiency)
- **出典**：https://www.langchain.com/blog/building-long-running-agents-with-scaledown-and-deep-agents
