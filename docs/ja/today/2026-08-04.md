# 2026-08-04

## Firecrawl が pdf-inspector を公開：ドキュメント解析の「一次トリアージ」コンポーネント

- **概要**：pdf-inspector（Rust）が 1 日で +1,699 スター（累計 8.2k）——Firecrawl が公開した軽量 PDF 検出ライブラリ：10-50ms で PDF をテキスト型/スキャン型/画像型/混合型に分類（信頼度付き。サンプリングしたコンテンツストリームのテキスト/画像オペレータを分析）、OCR なしで位置認識テキスト抽出とクリーンな Markdown 変換（表検出・多言語エンコーディング対応）、WebAssembly でブラウザ内ローカル実行、Python/Node バインディング付き。
- **なぜ重要か**：ドキュメント解析パイプラインの「一次トリアージ」が専用コンポーネント化された——まずミリ秒で PDF タイプを判定し、OCR か直接テキスト抽出へルーティングする。LlamaIndex Parse Gateway のページ単位ルーティングと同じ潮流の別粒度。WASM 対応はトリアージを完全に端末側で完結できることを意味し、機密文書がローカルから出ない。
- **分類**：RAG
- **関連 Topic**：[document-parsing](/ja/topics/document-parsing)
- **出典**：https://github.com/firecrawl/pdf-inspector

## DeepSeek-Reasonix が Trending に：ターミナルコーディングエージェントがモデル生態系で分化

- **概要**：DeepSeek-Reasonix（Go）が 2 日連続 Trending（日次 +883、累計 29.9k）——DeepSeek ネイティブのターミナルコーディングエージェント：単一の静的 Go バイナリで、provider/agent/ツール/プラグインをすべて `reasonix.toml` で宣言する設定駆動アーキテクチャ；DeepSeek の prefix cache を軸にコンテキスト管理を調律（キャッシュ安定性の維持、古いツール出力の刈り込み）して長セッションのコストを抑制；プラグインは stdio JSON-RPC のサブプロセスとして実行（MCP 互換）、任意の OpenAI 互換エンドポイントを設定で接続可能。
- **なぜ重要か**：ターミナルコーディングエージェントは独立したカテゴリとなり、モデル生態系ごとの分化が始まった——Claude Code の後に「DeepSeek ネイティブ」の対応物が登場。特定モデルのコスト構造（prefix cache）に合わせた harness レベルの調律は新しい差別化軸であり、単一バイナリ + 設定駆動はこのカテゴリのミニマリスト路線を代表する。
- **分類**：Coding
- **関連 Topic**：[coding-agents](/ja/topics/coding-agents)
- **出典**：https://github.com/esengine/DeepSeek-Reasonix
