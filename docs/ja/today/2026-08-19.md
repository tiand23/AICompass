# 2026-08-19

## OpenAI が Private Safety Processing をプレビュー：Zero Data Retention を壊さないまま複数回の対話をまたいだ悪用検知

- **概要**：OpenAI は早期顧客と共に Private Safety Processing のテストを進めていると発表した——Zero Data Retention（ZDR、ゼロデータ保持）へのコミットメントを維持したまま、複数回の関連する対話をまたいで悪用パターンを識別する安全モニタリングシステムだ。動機となっているのは、既存の ZDR 互換の安全システムが抱える限界である：これらは各対話を個別にしか評価できないが、モデルがより長く、より自律的なタスクを引き受けるようになるにつれ、一部の深刻なリスク（Agent が悪意ある形で誘導されて実行する長期タスクなど）は複数ターンをまたいで初めて可視化される。新システムは OpenAI 側に狭く定義された「安全シグナル」（例：疑わしい悪用のフラグ）のみを送信し、底流にある prompt や応答の内容自体は一切開示しない；顧客データは顧客が管理する基盤上に留めることも、OpenAI が保存しつつ暗号鍵は顧客側が保持することもできる。現時点では対象となるエンタープライズおよび API 顧客向けのテストに限定され、コンシューマー向け ChatGPT サブスクリプションは対象外；より広範な展開と技術白書は 9 月に予定されている。
- **なぜ重要か**：これは、これまで互いにトレードオフの関係にあるとみなされてきた「プライバシー保護」と「安全モニタリング」という 2 つの目標のあいだに、アーキテクチャレベルで具体的な折衷案を見出した事例だ。ZDR の代償は通常、安全チームが対話内容を一切可視化できなくなることだったが、Private Safety Processing は粒度を「内容」から「狭いシグナル」まで落とすことで、「生の内容を保持しないこと」と「対話をまたいだ悪用パターンの検知」が両立しうることを示そうとしている。長期的な自律タスクを Agent に委ねる企業顧客にとって、このようなセッションをまたいだ挙動モニタリングは、本ナレッジベースが継続的に追跡している「EDR for Agents」という物語が、受動的なランタイム検知（Uber ADR のような）から、モデルベンダー自身が推論時に提供するホスト型能力へと拡張する、また一つの実例と言える；報道はこれを Anthropic の既存のコンプライアンスログ保持要件に対する差別化競争としても位置づけている。
- **分類**：その他（セキュリティ）
- **関連 Topic**：[agentic-safety](/ja/topics/agentic-safety) ・ [openai-models](/ja/topics/openai-models)
- **出典**：https://techcrunch.com/2026/08/19/openai-seeks-to-one-up-anthropic-with-new-customer-privacy-protections/

## Claude Platform の Agent Skills API が正式 GA に；Managed Agents に Web ツールのドメイン許可/拒否リストを追加

- **概要**：Claude Platform のリリースノートが、一括で正式 GA（beta header 不要）となる API 群を発表した：①**Agent Skills と Skills API**（`/v1/skills`）が正式 GA に、`container` パラメータ経由で Messages API に Skill を読み込むリクエストも含む；②Files API（`/v1/files`）が正式 GA に、ファイル有効期限とページネーションを含む；③Claude Enterprise 組織向け Admin API のユーザー管理エンドポイント（メンバー、招待、グループ、カスタムロール）が正式 GA に。同時に Managed Agents に新しいセキュリティ制御が追加された：agent の `web_search`/`web_fetch` ツールに対して `allowed_domains` または `blocked_domains` を設定できるようになり、`web_fetch` は取得内容の長さを制限する `max_content_tokens` を、`web_search` は `user_location` をそれぞれサポートする。すべての変更は後方互換——旧 beta header を付けたリクエストは従来の形式のまま動作し続ける。
- **なぜ重要か**：Skills API が beta から正式 GA へ移行したことは、本ナレッジベースが 2025 年 10 月から追跡してきた急速に拡大する Skill エコシステム（「エコシステム熱度」ランキングにはすでに十数個の高スターなサードパーティリポジトリが並ぶ）に、ついに公式 API レベルでの本番運用の裏付けが与えられたことを意味する——サードパーティツールやエンタープライズ統合は、beta header がいつ変わるか気にする必要がなくなる。Managed Agents のドメイン許可/拒否リストは、最小権限原則がホスト型 Agent のネットワークアクセスという場面に具体的に落とし込まれた例だ——これまでこの原則は主にツール呼び出し権限や認証情報の注入レイヤーで現れていたが、今回は制御の粒度が「Agent がネットワーク経由でアクセスできる具体的なドメインはどれか」にまで下りてきており、ホスト型 Agent のセキュリティ設定項目が継続的に細分化されている一例だ。
- **分類**：Agent
- **関連 Topic**：[agent-skills](/ja/topics/agent-skills) ・ [cloud-agent-platforms](/ja/topics/cloud-agent-platforms)
- **出典**：https://platform.claude.com/docs/en/release-notes/overview

## LiquidAI が量子化認識蒸留（QAD）Q4_0 チェックポイントを発表：エッジモデルが BF16 の 96〜97% の性能を回復

- **概要**：LiquidAI が HuggingFace ブログで量子化認識蒸留（Quantization-Aware Distillation、QAD）技術を紹介し、LFM2.5 シリーズの 4 モデル（230M、350M、1.2B-Instruct、2.6B）向けに対応する QAD Q4_0 チェックポイントを発表した。訓練完了後にモデルを圧縮する後訓練量子化（PTQ）とは異なり、QAD は量子化のプロセスを蒸留訓練そのものに組み込む——高精度の教師モデルが量子化された生徒モデルの訓練を指導することで、モデルは最初から量子化の制約下で能力を保つことを学習し、訓練を終えてから圧縮するのではない。GPQA Diamond、MMLU-Pro、IFEval、GSM8K、AIME25 などのベンチマークにおいて、4 モデルの QAD Q4_0 チェックポイントはそれぞれ BF16 フル精度の 97.1%、96.5%、97.4%、96.6% の性能を回復した；同等の品質を得るために必要なより高ビットの量子化版（小型モデルは Q5_K_M、大型モデルは Q4_K_M）と比較すると、QAD Q4_0 のデコードスループットは 4〜33%（小型モデル）、3〜14%（大型モデル）高い。対象となるエッジハードウェアには MacBook Pro、NucBox EVO-X2、Samsung Galaxy S26 Ultra、Raspberry Pi 5 が含まれ、モデルは LFM1.0 ライセンスの下で公開される。
- **なぜ重要か**：これは低ビット量子化という効率化の路線における具体的な方法論の融合だ——量子化を事後の圧縮ステップから訓練時の最適化目標そのものへと作り替え、蒸留によって量子化がもたらす精度低下を補うことで、これまで別々だった 2 つの技術路線（量子化と知識蒸留）を合流させている。96% 超の精度を保ちながら二桁パーセントのスループット向上も得られるという結果は、エッジデプロイにとって特に意味がある——この種のシナリオではしばしば 4-bit 精度での実行が必須で、これまでは精度と速度の間でより厳しいトレードオフを迫られていた。QAD は「両方とも手に入れる」ための具体的な道筋を示しており、Liquid AI がエッジモデルの効率化という製品ラインを継続的に深めている進展の一つでもある（詳細は [model-efficiency](/ja/topics/model-efficiency)）。
- **分類**：Models
- **関連 Topic**：[model-efficiency](/ja/topics/model-efficiency)
- **出典**：https://huggingface.co/blog/LiquidAI/qad

## Claude API がブラウザ使用ツールを追加、コンピュータ使用ツールが GA に、Managed Agents のサンドボックスが記憶ストア接続に対応（補漏）

- **概要**：Claude Platform が同じバッチで 3 件の Agent ツール関連アップデートを発表した：①**ブラウザ使用ツール**（`browser_toolset_20260801`）——デスクトップ全体を操作するコンピュータ使用ツールとは異なり、ブラウザのビューポート内のみで動作し、ページの無障害ツリー/要素/フォーム/タブを直接読み取る。要素の特定、フォーム入力、タブ管理、ダウンロードの報告、任意のファイルアップロードに対応；②**コンピュータ使用ツール**（`computer_toolset_20260801`）が正式 GA に、beta header 不要となり、バッチアクション、デフォルトでの zoom 有効化、メンバー単位の設定を追加；③Managed Agents の自托管サンドボックスで動くセッションが**記憶ストア**の接続に対応——SDK worker がセッション開始時にストアをサンドボックスにダウンロードし、Agent が生じた変更をストアへ同期する。3 つとも Fable 5、Mythos 5、Opus 5、Sonnet 5、Opus 4.8 で利用可能。
- **なぜ重要か**：「コンピュータ操作」を「デスクトップ全体の制御」と「ブラウザ内操作」に分けたことは、ツール設計における最小権限原則の具体的な実装だ——ほとんどのタスクはブラウザアクセスだけで済み、デスクトップ全体の制御権を与えるのは不要な攻撃面になる；スクリーンショット＋クリックではなく無障害ツリーを読むことで、ブラウザ自動化が視覚モデルの精度に依存しなくなる。記憶ストアをサンドボックスセッションに直接接続できるようになったことは、Agent の記憶能力をホスト型実行環境そのものへ落とし込むものだ（詳細は [agent-memory](/ja/topics/agent-memory)）。
- **分類**：Agent
- **関連 Topic**：[agent-sandboxes](/ja/topics/agent-sandboxes) ・ [agent-memory](/ja/topics/agent-memory) ・ [cloud-agent-platforms](/ja/topics/cloud-agent-platforms)
- **出典**：https://platform.claude.com/docs/en/release-notes/overview
