## LlamaIndex が論証：文書 OCR は前沿モデルにコモディティ化されない

- **概要**：LlamaIndex が「Document OCR is Not Getting Commoditized」を公開：ParseBench のデータでは専用解析エンジンが GPT-5.5 を約 20 ポイント上回り、コストも低い。前沿モデルの視覚的位置特定（spatial grounding）はわずか約 8% で、専用エンジンは 55-80%。さらに各ラボのポストトレーニング計算資源は数学/コーディング/エージェントに向けられ、文書読解は優先されていない（GPT-5 system card にも Gemini 3 のリリースノートにも文書解析の改善への言及なし）。
- **なぜ重要か**：「前沿モデルがもっと強くなれば専用パーサーは不要になる」という選定時によくある判断への直接の反論——空間的位置特定の差は構造的：エージェントの証拠チェーンは「データがどのページのどの位置から来たか」を必要とする。4 つの「蒸留戦略」（複雑度によるルーティング、専門 RL ポストトレーニング、PDF テキスト層/OOXML などネイティブメタデータの活用、閉ループ評価）が優位性を持続させる。ParseBench は LlamaIndex 自社ベンチマークで立場のある議論だが、構造的な論拠は長期の選定判断に取り込む価値がある。
- **分類**：RAG
- **関連 Topic**：[document-parsing](/ja/topics/document-parsing)
- **出典**：https://www.llamaindex.ai/blog/document-ocr-is-not-getting-commoditized

## Uber が ADR をオープンソース化：エンタープライズ向け AI エージェント検知・対応システム

- **概要**：Uber が ADR（Agentic AI Detection and Response）をオープンソース化——Uber の本番環境で稼働中のエージェントセキュリティシステム：Sensor が macOS/Linux/Windows 上の 7+ のコーディングエージェント（Claude Code/Cursor/Codex 等）の意図・ツール呼び出し・実行トレースを収集；ADR-Bench は 300+ タスクと 133 の MCP サーバーでセキュリティベンチマークを構築；検知は 2 層アーキテクチャ（高再現率のトリアージ + 疑わしいセッションへの深い agentic 推論）。阻止モジュールは非公開。論文は MLSys 2026 に採択。
- **なぜ重要か**：「EDR for Agents」というカテゴリの登場——エンドポイントセキュリティの「検知と対応」パラダイムをエージェントの挙動に移植したもので、セキュリティベンダーのコンセプト資料ではなく大手企業の本番実践から出てきた。ADR-Bench は MCP サーバーを攻撃面として体系的にテストする初のベンチマークでもある。これでエージェントセキュリティのツールチェーンは 3 ピースが揃った：ガバナンス（agent-governance-toolkit）、評価の透明性（Anthropic レッドチーム検証）、ランタイム検知（ADR）。
- **分類**：その他

## video-use が GitHub Trending に：フレームを消費せず転写でコーディングエージェントに動画編集させる

- **概要**：browser-use チームが video-use（累計 19.5k スター）を公開、1 日で +320——Claude Code などのコーディングエージェントに自然言語で動画編集させる：フィラーワード/無音の除去、カラーグレーディング、カット点での音声フェード、字幕焼き込み、アニメーションオーバーレイの生成を行い、各カット境界で自らレンダリングと自己評価を行う。鍵となる設計は、モデルに生の動画フレームを直接食わせない（トークン予算が爆発する）こと——まず ElevenLabs Scribe で音声を単語レベルのタイムスタンプ付き文字起こし（約 12KB）に変換し、必要な時だけフィルムストリップと波形の PNG 合成画像で視覚分析を行う。パイプラインは 転写→パック→LLM 推論→EDL→レンダリング→自己評価。

- **分類**：Coding

## Claude が Inference Hooks を導入：推論の手前に立つリアルタイムポリシーゲートウェイ

- **概要**：Claude Enterprise に Inference Hooks（beta）が追加——claude.ai、Cowork、Claude Code を横断するすべての管理対象 prompt が、実際の推論が始まる前に組織自前の「AI セキュリティサーバー」へ同期 POST され、allow/deny の裁定を待つ（デフォルトタイムアウト 5 秒、Standard Webhooks 仕様に基づく署名）。deny の場合、ユーザーはモデルの回答を一切見ず、ポリシーによるブロックメッセージだけを見る。サーバーが受け取るのはユーザーが見ているのと同じ内容（文字起こし、ツール呼び出しと結果、添付ファイルから抽出したテキスト）のみで、システムプロンプトや生のファイルバイト列は渡されない。シャドーモードや割合指定のロールアウトから始められ、初日から全件ブロックする必要はない。
- **なぜ重要か**：「推論」そのものが公式に**ポリシーゲートウェイが差し込める一工程**として開放されたのは初めて——これまで Claude の Compliance API は事後の追跡しかできなかった。Inference Hooks は DLP、モデル許可リスト、就業時間制限といったルールを推論前のリアルタイムでブロックできるようにする。同日公開された Uber の ADR（事中/事後の挙動検知）と組み合わせると、企業エージェントのセキュリティは「事前ブロック（Inference Hooks）— 事中/事後検知（ADR）」という一連の鎖を完成させつつある。現時点では claude.ai/Cowork/Claude Code のみが対象で、Bedrock/Vertex/Platform API は対象外。
- **分類**：その他（セキュリティ）
- **関連 Topic**：[agentic-safety](/ja/topics/agentic-safety) ・ [claude-models](/ja/topics/claude-models)
- **出典**：https://platform.claude.com/docs/en/manage-claude/inference-hooks

## LangChain が Kubernetes 自律 SRE エージェント事例を公開：読み取りは自律、書き込みは必ず人を通す

- **概要**：LangChain が Deep Agents 上に構築した Kubernetes 自律 SRE エージェントを詳解——スケジューラが軽量な定期ヘルスチェックを実行（素の Python + 1 回の Haiku 呼び出し）、異常検知後は並列で専門サブエージェント（pod-inspector、scaling-analyzer、log-analyzer、security-auditor 等）を起動して深掘り調査、Sonnet 駆動のオーケストレーターが診断を統合し Slack 経由で修正案を提示する——ただし実行モジュールは厳格に人間の承認の後ろにゲートされている。設計上の鉄則は「読み取りは自律、書き込みは常に HITL でゲート」で、承認範囲も意図的に狭く保たれ、Helm アップグレードのような広範囲で影響の大きいコマンドの一括承認は許されない。
- **なぜ重要か**：「コストで階層分けしたモデル運用」（頻度の高い軽量チェックは安いモデル、深い推論が要る時だけ高価なモデル）と「読み書き権限の分離」という 2 つの原則を実運用のオペレーションで同時に示した好例——Agent をインフラ運用に投入したいが「暴走」を恐れているチームにとって、そのまま流用できるアーキテクチャパターン。特に「承認範囲を人が理解できるほど狭く保つ」は「人間の承認を入れる」という漠然としたアドバイスより遥かに実行可能。
- **分類**：Agent
- **関連 Topic**：[deep-agents](/ja/topics/deep-agents) ・ [enterprise-ai-agents](/ja/topics/enterprise-ai-agents)
- **出典**：https://www.langchain.com/blog/how-we-build-an-autonomous-sre-agent-for-kubernetes-deployments
