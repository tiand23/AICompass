# 2026-08-05

## LlamaIndex が論証：文書 OCR は前沿モデルにコモディティ化されない

- **概要**：LlamaIndex が「Document OCR is Not Getting Commoditized」を公開：ParseBench のデータでは専用解析エンジンが GPT-5.5 を約 20 ポイント上回り、コストも低い。前沿モデルの視覚的位置特定（spatial grounding）はわずか約 8% で、専用エンジンは 55-80%。さらに各ラボのポストトレーニング計算資源は数学/コーディング/エージェントに向けられ、文書読解は優先されていない（GPT-5 system card にも Gemini 3 のリリースノートにも文書解析の改善への言及なし）。
- **なぜ重要か**：「前沿モデルがもっと強くなれば専用パーサーは不要になる」という選定時によくある判断への直接の反論——空間的位置特定の差は構造的：エージェントの証拠チェーンは「データがどのページのどの位置から来たか」を必要とする。4 つの「蒸留戦略」（複雑度によるルーティング、専門 RL ポストトレーニング、PDF テキスト層/OOXML などネイティブメタデータの活用、閉ループ評価）が優位性を持続させる。ParseBench は LlamaIndex 自社ベンチマークで立場のある議論だが、構造的な論拠は長期の選定判断に取り込む価値がある。
- **分類**：RAG
- **関連 Topic**：[document-parsing](/ja/topics/document-parsing)
- **出典**：https://www.llamaindex.ai/blog/document-ocr-is-not-getting-commoditized

## Uber が ADR をオープンソース化：エンタープライズ向け AI エージェント検知・対応システム

- **概要**：Uber が ADR（Agentic AI Detection and Response）をオープンソース化——Uber の本番環境で稼働中のエージェントセキュリティシステム：Sensor が macOS/Linux/Windows 上の 7+ のコーディングエージェント（Claude Code/Cursor/Codex 等）の意図・ツール呼び出し・実行トレースを収集；ADR-Bench は 300+ タスクと 133 の MCP サーバーでセキュリティベンチマークを構築；検知は 2 層アーキテクチャ（高再現率のトリアージ + 疑わしいセッションへの深い agentic 推論）。阻止モジュールは非公開。論文は MLSys 2026 に採択。
- **なぜ重要か**：「EDR for Agents」というカテゴリの登場——エンドポイントセキュリティの「検知と対応」パラダイムをエージェントの挙動に移植したもので、セキュリティベンダーのコンセプト資料ではなく大手企業の本番実践から出てきた。ADR-Bench は MCP サーバーを攻撃面として体系的にテストする初のベンチマークでもある。これでエージェントセキュリティのツールチェーンは 3 ピースが揃った：ガバナンス（agent-governance-toolkit）、評価の透明性（Anthropic レッドチーム検証）、ランタイム検知（ADR）。
- **分類**：その他
- **関連 Topic**：[agentic-safety](/ja/topics/agentic-safety)
- **出典**：https://github.com/uber/ADR
