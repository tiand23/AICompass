# Document Parsing

## 概要

ドキュメント解析と構造化：PDF・スキャン・表・図を LLM が使える構造化データ（Markdown/JSON）に変換する。2026 年の主流は **VLM（視覚言語モデル）+ 意味再構築のエージェント型解析**で、テンプレート OCR と従来型 IDP を置き換えつつある。代表ツール：LlamaParse/LlamaExtract、Docling、Reducto、Unstructured。

## なぜ重要か

企業ナレッジの 8 割は非構造化文書の中にあり、解析品質が RAG/ナレッジベースパイプライン全体の天井になる——ゴミを入れればゴミが出る。この層の世代交代（テンプレート → 意味理解）は今まさに進行中で、文書系アプリの実現可能性の境界を直接動かしている。

## コアコンセプト

- **エージェント型解析 vs テンプレート OCR**：テンプレートは固定レイアウトで抽出し、新レイアウトで壊れる；エージェント型解析は人間のように構造を理解し（章の階層、表、図注）、レイアウト変化に免疫がある。
- **意味再構築**：文字だけでなく文書の論理構造を復元する——RAG チャンキング品質の前提。
- **スキーマベース構造化抽出**：目標フィールドの schema を定義し型付き JSON を直接得る（LlamaExtract など）——きれいな構造化データへの最も確実な道。
- **選定メモ**：LlamaParse は RAG スタック向けの本番成熟度が最高；Docling はプライバシー重視のセルフホストに適合（技術・科学文書に特に強い）；Reducto は LongExtractBench で精度/再現率 99.6% の首位。
- **空間的位置特定（spatial grounding）**：専用パーサーと汎用大規模モデルの構造的な差——前沿モデルの ParseBench 視覚的位置特定は約 8%、専用エンジンは 55-80%。エージェントの証拠チェーンは「どのページのどの位置か」を必要とし、「OCR はコモディティ化されない」論の核心的根拠。
- **「流暢な」エラーは「文字化け」エラーより危険**：従来型 OCR は肉眼で分かる壊れたゴミとして失敗するが、LLM OCR は流暢で一見もっともらしいが誤った文章として失敗する——視覚的証拠が曖昧な場合、モデルは「画像が最も裏付けるテキスト」より「テキストとして最もありそうなもの」を選好し、口座番号や部品番号のような高エントロピー文字列は言語の事前分布が最も弱い箇所であるがゆえに特に脆弱。
- **ページ平均の指標は重要フィールドのエラーを覆い隠す**：文字/単語誤り率はページ全体で平均を取るため、99% の精度と報告されたページでも誤った 1% が合計金額や識別子であれば無価値になりうる——受け入れ検査はページ全体の平均スコアではなく、フィールドタイプ（特に高エントロピーのフィールド）ごとに精度を測定すべき。
- **大規模解析パイプラインのスケジューリング基盤としての永続ワークフロー**：文書処理は本質的に長時間・多段階・失敗しやすいシナリオだ（1 件の文書に OCR + 視覚モデル + 複数回の処理が必要になることもある）——Temporal のような永続ワークフローエンジンで「リソース調整」自体を可観測なワークフローエンティティとしてモデル化する（例：信号量 Workflow で並行性制御）方が手書きのロック/リトライカウンタより信頼性が高く、失敗したジョブは最初からやり直すのではなくチェックポイントから再開できる（詳細は [agent-workflow](/ja/topics/agent-workflow)）。

## Timeline

### [2026-08-31](/ja/today/2026-08-31)

Cohere が Parse V5 を発表し Microsoft Foundry に登場：文書解析専用の 23 億パラメータ視覚言語モデルで、PDF/PPT/JPEG ページを読み順を保った Markdown、HTML 形式のテーブル、フォームのキー・バリュー、画像説明、バウンディングボックス座標に変換する。金融・保険・科学研究などの分野の文書をカバーし、主要 9 言語に対応、GPU 1 台あたり毎秒約 4.5 ページを処理。ベンチマークでは最高精度ではないが、1,000 ページあたり 1.5 ドルというコストで優位に立つ。現在 Cohere API、Model Vault、Microsoft Foundry、AWS SageMaker から利用可能で、Foundry にデプロイした場合は推論が顧客の Azure テナント境界内に留まる。「ページ平均指標が重要フィールドのエラーを覆い隠す」という繰り返し指摘されてきた論点を裏付け、「コスト」を独立した選定軸として前面に押し出す解析分野の多目的トレードオフ移行の具体例の一つ。

### [2026-08-17](/ja/today/2026-08-17)

LlamaIndex が Temporal で文書処理のスケジューリングを再構築した詳細を公開：ネイティブな永続性/公平性プリミティブを欠く自前の RabbitMQ システムから Workflow+Activity モデルへ移行、信号量 Workflow で並行性制御、「永続的な関数実行」でマシン OOM によるジョブの静かな死を解消——現在 130 以上のファイル形式に対応し日次数千万ページを処理（詳細は [agent-workflow](/ja/topics/agent-workflow)）。

### [2026-08-12](/ja/today/2026-08-12)

LlamaIndex は LLM OCR のエラーが減っているのではなく静かになっているだけだと論じる：3 つの主流アーキテクチャ（OCR+LLM 訂正、VLM ネイティブ転写、agentic セグメンテーション+ルーティング）を分解し、それぞれの独自の壊れ方を示す。核心メカニズムは、視覚信号が曖昧な場合にモデルが画像証拠より言語の事前分布を選好すること、そして CER/WER 系のページ平均指標が重要フィールドのエラーを覆い隠すこと——本番システムにはセグメンテーション、ルーティング、検証ループ、ピクセルレベルの引用といったアーキテクチャレベルの制御が必要。

### [2026-08-11](/ja/today/2026-08-11)

LlamaIndex が ExtractBench を発表：370 件の実企業文書、14 の抽出システムを完全性・根拠性・ページあたりコストで評価するオープンベンチマーク——1 週間前の「OCR はコモディティ化されない」立場記事に対する再現可能なデータの続編で、「専用パーサー vs 汎用モデル」選定論争を主張から実測比較へ変えた。

### [2026-08-05](/ja/today/2026-08-05)

LlamaIndex が「文書 OCR は前沿モデルにコモディティ化されない」と論証：ParseBench で専用エンジンが GPT-5.5 を約 20 ポイント上回りコストも低い。視覚的位置特定の差（8% vs 55-80%）は構造的で、ラボのポストトレーニング資源は文書読解に向かわない。自社ベンチマークゆえ立場はあるが、論拠は長期の選定判断に値する。

### [2026-08-04](/ja/today/2026-08-04)
