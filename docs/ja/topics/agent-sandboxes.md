# Agent Sandboxes

## 概要

Agent サンドボックス：AI Agent にコードを実行し、ファイルシステムをマウントし、ネットワークにアクセスするための隔離実行環境を提供するインフラ層——本質的には「Agent のためのコンピュータ」。代表製品：E2B、Daytona、Modal Sandboxes、そしてクラウドベンダー自身が構築した Cloudflare computer。ユーザー向けのデスクトップ型ワークスペース製品である [agent-workspaces](/ja/topics/agent-workspaces) とは異なり、サンドボックスはより低レイヤーの開発者向けインフラの構成要素である。

## なぜ重要か

Agent が（コードの提案だけでなく）実際にコードを実行して結果を検証する必要が出てくると、安全で制御可能かつ再利用可能な実行環境が必須になる——ホストマシンに直接実行させるわけにも、毎回フル VM をコールドスタートさせるわけにもいかない。この層の隔離強度、起動速度、状態永続化能力が、コーディング Agent やディープリサーチ Agent がどれだけ速く、安全に、安く動けるかを直接左右する。また [agentic-safety](/ja/topics/agentic-safety) における「サンドボックス脱出」リスクの直接の受け皿でもある——サンドボックス設計の良し悪しは、そのままセキュリティ境界の正確さである。

## コアコンセプト

- **ストレージ層と隔離層の分離**：ファイルシステム状態（例：SQLite に保存）と実行バックエンド（コンテナ/隔離シェル/隔離 JS ランタイム）を分離し、同じワークスペース状態を必要に応じて隔離強度を切り替えられるようにする——1 種類のサンドボックス形態に固定しない（Cloudflare computer の設計方針）。
- **隔離強度のスペクトラム**：プロセスレベル隔離（速く軽いが隔離は弱い）からマイクロ VM/コンテナ（やや遅いが隔離が強く、完全な Linux ユーザーランドと実ネットワークアクセスを実行可能）まで——一律に最も重い方式を使うのではなく、タスクのリスクに応じて強度を選ぶ。
- **コールドスタートと再利用**：オンデマンドでのサンドボックス作成・破棄はコストが高い。ホスト型サンドボックスプラットフォームは総じて秒未満のコールドスタートとサンドボックスプールの再利用を最適化している。
- **統一実行エントリポイント**：複数のバックエンドが単一の呼び出しインターフェース（例：`workspace.runtime.exec()`）の背後に隠蔽され、上位の Agent ロジックは具体的な隔離実装を意識しなくてよい。
- **コンテナレベル隔離の現実のリスク**：カーネルを共有するコンテナは、信頼できない・モデルが生成したコードを実行する Agent の隔離には不十分——2025 年 9 月の Shai-Hulud npm ワーム（preinstall スクリプト経由で 500 以上のパッケージを汚染）や CVE-2026-31431（732 バイトの Python スクリプトで主要 Linux ディストリビューションを root 化）が具体的な失敗事例。ハードウェア仮想化 microVM（独立カーネル）はより強い隔離の選択肢。
- **ツールの積み増し vs 計算環境**：Agent に数十〜数百の事前定義ツールを詰め込んでも収益は逓減し、コンテキストを汚染する（monday.com の Sidekick は 200 以上のツールで鈍く高コストになった）。永続的にコードを実行でき、動的に適応できるサンドボックス環境を与える方が、網羅的なツールカタログより実際の能力上限に近い。

## ベストプラクティス

- タスクのリスクに応じて隔離強度を選ぶ：読み取り専用の分析には軽量な隔離で十分、ネットワークアクセスやシステムコールを伴うタスクには強い隔離を。
- サンドボックスはデフォルトでネットワーク遮断、または許可リスト付きプロキシ経由とし、認証情報はセッション単位で最小限に注入する——Agent の権限管理と同じ原則。
- 本番環境で「プレビューのみ」段階のサンドボックス製品を使う際は慎重に——隔離境界がセキュリティ監査を経ているか先に確認する。

## Timeline

### [2026-08-19](/ja/today/2026-08-19)（補漏）

Claude API がブラウザ使用ツール（`browser_toolset_20260801`）を発表：デスクトップ全体を操作するコンピュータ使用ツールとは異なり、ブラウザのビューポート内のみで動作し、スクリーンショット＋クリックではなくページの無障害ツリー/要素/フォームを直接読み取る。要素の特定、フォーム入力、タブ管理、任意のファイルアップロードに対応——「デスクトップ全体の制御」と「ブラウザ内操作」を分離することは、ツール設計における最小権限原則の具体的な実装だ。同日コンピュータ使用ツールが正式 GA に（詳細は [claude-models](/ja/topics/claude-models)）。

### [2026-08-11](/ja/today/2026-08-11)

LangChain が「Give your agent its own computer」を公開、monday.com Sidekick を事例に取り上げる：200 以上の事前定義ツールがコンテキスト汚染を招き、性能低下とコスト増を引き起こしていたが、LangSmith Sandboxes（ハードウェア仮想化 microVM。カーネル共有コンテナではない）に切り替えたことで、Agent は独自のファイルシステム/shell/ネットワーク/セッション横断永続状態を獲得し、能力が大きく向上した。記事は Shai-Hulud npm ワームと CVE-2026-31431 という 2 件の実際のコンテナ脱出/サプライチェーンリスク事例も挙げ、カーネル共有コンテナがモデル生成コードの隔離には不十分だと論じる（詳細は [deep-agents](/ja/topics/deep-agents)）。

### [2026-08-06](/ja/today/2026-08-06)

Cloudflare が computer をオープンソース化：Durable Object 内の仮想ファイルシステム + 3 種の差し替え可能な実行バックエンド（Container/Isolate Shell/Isolate JavaScript）で、ストレージ層と隔離層を独立して差し替え可能なコンポーネントに分離。現時点ではプレビュー段階のみ。Agent サンドボックスが独立したインフラ層として建档される起点。
