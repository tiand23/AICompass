# Agent Workflow

## 概要

エージェントワークフロー開発：ビジネスプロセスを「決定論的オーケストレーション + モデルの自律判断」の組み合わせとして表現する——グラフ/ステートマシンによる編成、human-in-the-loop 承認ノード、永続実行（durable execution）、エラー回復とリトライ。

## なぜ重要か

「完全自律エージェント」は 2026 年の企業の現実ではまだ少数派——主流は **assisted workflow**：人がレビューし、エージェントが実行する。ワークフロー設計（どこでモデルに自由を与え、どこを決定論で縛り、どこで人のサインを必須にするか）は企業エージェントプロジェクトの成否を分ける最初の設計判断であり、モデル選定より重要。

## コアコンセプト

- **決定論—自律のスペクトラム**：純パイプライン（予測可能だが硬直）→ グラフ編成 + 制限付き判断（主流のスイートスポット）→ 完全自律計画（Deep Agents の方向。評価と信頼がボトルネック）。
- **Human-in-the-loop ノード**：破壊的操作前の承認ゲート。設計要点は「人のレビュー」を低摩擦にすること——さもないと迂回される。
- **永続実行**：長いプロセスは時間/日単位で中断・再開できる必要がある（承認待ち、外部システム待ち）。状態はメモリではなくディスクに。
- **ロールバック可能性**：グラフアーキテクチャが普及した実際の理由——各ノードが自然な監査点・ロールバック点になる。

## ベストプラクティス

- 「モデルの自由度最小」のバージョンから本番投入し、実運用データで段階的に権限を広げる——常に「賢さより信頼性が先」。
- すべての自律判断ポイントに 3 点セットを付ける：確信度による出口（不確実なら人へエスカレーション）、タイムアウト予算、失敗時の決定論的フォールバック経路。
