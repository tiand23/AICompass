# Model Efficiency

## 概要

モデルの効率化と小型化：より少ない計算資源で使えるインテリジェンスを引き出す——小規模言語モデル（SLM）、知識蒸留、低ビット量子化、効率的アーキテクチャ（Liquid AI の非 Transformer 系 LFM など）、CPU/エッジ推論。

## なぜ重要か

フロンティアモデルは巨大化し続けるが、本番ワークロードの多く（分類、埋め込み、抽出、ルーティング）にフロンティア級の知能は不要——必要なのは**十分・安価・高速**。効率化技術は AI アプリのユニットエコノミクスとデプロイ境界（CPU・エッジ・オンプレで動くか）を決める、「生成 AI の大規模実装」の見えない土台。

## コアコンセプト

- **SLM**：数億〜数十億パラメータの専用モデル。蒸留と組み合わせれば狭いタスクで大型モデルの品質に迫る。
- **知識蒸留**：大型モデル（教師）の出力で小型モデル（生徒）を訓練し、能力を小さな器に圧縮する。
- **低ビット量子化**：4-bit などの精度圧縮で VRAM とレイテンシを大幅削減（拡散モデル側の Nunchaku を参照）。
- **効率的アーキテクチャ**：Liquid AI の LFM など非 Transformer 路線。同等品質で桁違いに低い推論コストを狙う。
- **CPU/エッジ推論**：GPU に依存しないデプロイ形態——embedding・エンコーダ系負荷では既に実用段階。
- **階層ロード推論**：重みをレイヤーごとにロードし時間で VRAM を買う（airllm：4GB GPU で 70B）。品質は落ちないが速度を犠牲に——低頻度オフラインタスク向け、量子化/蒸留と相互補完。
- **ローカル Agentic マルチモーダルオープンモデル**：新興のモデル群（Meta Muse Glimmer など）は「ローカル実行可能・Agentic・マルチモーダル・オープンソース」を同時に満たし、ゲート付き GQA などのメモリ最適化技術でパラメータ数をコンシューマー向けハードウェアが許容できる範囲に抑える——単なる小型分類/埋め込みモデルではない。
- **実行時モデルルーティング**：小型モデルを訓練するのではなく、Agent の実行時に呼び出しを安価/高価なモデル間で動的に振り分ける——LangChain の NVIDIA Switchyard 実測では、Deep Agents 評価セットの呼び出しの 93% が 30B モデルにルーティングされ、前沿モデルが必要なのはわずか 7%、コストは 74% 削減された。割に合うかどうかは判断モデルのコストと 2 階層のモデルの価格差の比率次第——価格差が大きいほどルーティングは割に合う。
- **極小体積の専門特化モデル**：汎用的な対話品質を追わず、ツール呼び出し/構造化抽出のような狭いタスクに特化し、積極的な量子化で体積を極限まで圧縮する（needle：14MB 単一ファイル、実行時メモリ約 28MB、スマホ/ウェアラブル/ロボット向け）——SLM 路線の体積軸における極端なサンプルで、「十分であればよい」という効率哲学と一貫する。
- **ローカル訓練/推論がコマンドラインから GUI へ**：Unsloth Desktop は、これまでスクリプト駆動だったローカルファインチューニング（LLM と画像/動画拡散モデルの LoRA）をデスクトップ GUI にまとめ、`unsloth start` で Claude Code/Codex などのコーディング Agent に直結する——ローカル効率化ツールの使いやすさの敷居が下がりつつあり、効率化数値そのものだけが進化しているのではない（詳細は [coding-agents](/ja/topics/coding-agents)）。
- **エッジ向け視覚言語モデル**：Liquid AI LFM2.5-VL-3B は SLM 路線をテキスト単体からマルチモーダルへ拡張——UI 理解、画面定位、複数画像入力を 3B パラメータ・約 3GB メモリのエッジモデルに詰め込み、文書/OCR、定位系ベンチマークではより大きな 4B 級モデルに匹敵する。「体積を圧縮する」ことと「大型モデルに引けを取らない」ことは両立できると証明した。
- **ダウンロード数と注目度の分岐**：10 億パラメータ未満のモデルが全プラットフォーム史上ダウンロード数の 83% を占め、1000 億パラメータ超はわずか 1%——ダウンロードは本番パイプラインへの組み込みを、いいねは一時的な盛り上がりを反映するにすぎず、2 つのランキングはほとんど重ならない；ローカル推論インフラ（GGUF 等）のリポジトリ増加率（464%）はコア建模ツール自体（21%）をはるかに上回る——効率化路線がインフラ層で加速しているシグナル（HuggingFace《2026 夏季オープンモデル現状》）。
- **量子化認識蒸留（QAD）**：訓練完了後にモデルを圧縮する後訓練量子化（PTQ）とは異なり、QAD は量子化を蒸留訓練そのものに組み込む——高精度の教師モデルが量子化された生徒モデルの訓練を指導し、モデルは最初から量子化の制約下で能力を保つことを学習する。LiquidAI が LFM2.5 シリーズの 4 モデルで実測したところ、QAD Q4_0 チェックポイントは BF16 の 96.5〜97.4% の性能を回復しつつ、同等品質に必要なより高ビットの量子化版より 3〜33% 高いスループットを達成した——これまで別々だった量子化と知識蒸留の 2 つの路線を融合するものだ。

## ベストプラクティス

- モデルを選ぶ前に「この工程にどれだけの知能が必要か」を問う——ルーティング・抽出・埋め込みは SLM/エンコーダで、大型モデルの予算は本当に難しい推論に残す。
- 量子化・小型化後は必ず自前の評価セットで回帰テストする。品質劣化はタスク依存。
