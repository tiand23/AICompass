# RAG

## 概要

RAG（Retrieval-Augmented Generation、検索拡張生成）：LLM が生成の前後・途中に外部知識（ドキュメントストア、ベクトルデータベース、DB、グラフ）を検索し、事実に基づいて回答するアーキテクチャ。ナレッジベース系アプリの中核であり、企業が生成 AI を導入する際の最も一般的なパターン。

## なぜ重要か

モデルのパラメータには私有知識は入らず、知識の更新にも追いつけない——RAG は「何を知っているか」を検索で解決し、モデルを「どう言うか」に集中させ、同時に出典引用による追跡可能性を提供する。企業にとっては社内文書・規程・業務データを LLM に接続する標準手法であり、ファインチューニングよりはるかに安価で即時更新が可能。

## コアコンセプト

- **古典的パイプライン（2023–2025）**：クエリをベクトル化 → top-k 検索 → コンテキストに投入 → 生成。シンプルだが硬直的で、検索精度が悪ければ全てが崩れる。
- **Agentic RAG（2026 年の主流）**：検索の意思決定をモデルの推論フローに埋め込む——いつ・何を検索するか、結果が十分かをモデルが自律判断。計画 → 検索 → 批判 → 書き直し → 内省のループを回し、検索と検証を専門エージェントが並行分担する。
- **先端方向**：長文書メモリ、適応的検索（簡単な質問は検索しない）、マルチモーダル grounding、グラフ推論（GraphRAG）、検索セキュリティ。グラフを独立した基盤層（決定論的推論、意思決定の来歴管理）として使う用法は [knowledge-graph](/ja/topics/knowledge-graph) を参照。
- **エンタープライズの前提**：アクセス制御・メタデータ・コンテキストのガバナンスが検索に先行しなければならない——ガバナンスなき企業 RAG は必ず失敗する。

## ベストプラクティス

- 新規プロジェクトは Agentic 前提で設計（検索タイミングをモデルに判断させる）しつつ、まず最小パイプラインでデータ品質を検証してからループを追加する。
- ガバナンスが先、検索は後：権限とメタデータの体系が整う前に機微なデータストアを RAG に接続しない。
- 評価駆動：正解付きの検索評価セットを作り、パイプライン変更のたびに回す——感覚で調整しない。
