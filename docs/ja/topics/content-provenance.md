# Content Provenance

## 概要

AI コンテンツの来歴標識と検証：透かし（Google SynthID など）と署名付きメタデータ（C2PA 標準）で AI 生成コンテンツをマークし、検出ツール/API であるコンテンツが AI 由来かを検証する。2026 年の鍵となる進展はベンダー横断の収斂——OpenAI も Google の SynthID を採用し C2PA に参加、透かしは各社独自方式から事実上の標準へ動き出した。

## なぜ重要か

生成コンテンツ（画像・音声・動画）のリアルさは人間の知覚で見分けられる閾値を越え、偽造検出は「研究課題」から「コンプライアンス上の必須要件」になった。開発者にとっての実際的な意義は検証 API の登場：コンテンツプラットフォームや企業のコンプライアンスフローが「AI 生成か否か」をプログラマブルなチェック項目として自らのパイプラインに組み込める——第三者検出サービスの推測に頼る必要がなくなる。

## コアコンセプト

- **透かし（SynthID）**：生成時に人の目・耳では知覚できないシグナルを埋め込む。切り抜きや圧縮など一般的な変換への一定の頑健性を持つ。Google が開発し、2026 年に OpenAI が採用。画像と音声をカバー。
- **テキスト透かし（Claude）**：画像/音声の透かしとは本質的に異なる路線——独立した信号を埋め込むのではなく、生成時のリスクの低い単語選択に使われるランダム性の源を書き換える方式で、鍵と直前の文脈が共同で単語選択を偏らせる。単一の選択は検出不能だが、十分な長さのテキストは統計的に検出可能。テキストの離散的・低次元的な性質ゆえに、音声/動画が持つような「透かしを隠せる冗長な信号空間」を欠くため、まったく異なる技術路線を取っている。
- **署名付きメタデータ（C2PA）**：コンテンツ資格情報（Content Credentials）の業界標準。生成来歴と編集履歴をファイルメタデータに記録。剥離可能なため透かしと相互補完。
- **検証ツールと API**：OpenAI の公開検証ツールなど。アップロードされたファイルに OpenAI 由来のシグナル（C2PA + SynthID）が含まれるかを確認、画像と音声に対応し、プログラム統合用の API も提供。
- **限界**：透かしは「協力する生成側」しかカバーしない——オープンウェイトモデルや透かしを入れないサービスの生成物は検出できない。来歴検証は「陽性は信頼できる」ものであり、陰性は非 AI を意味しない。Claude のテキスト透かしも同様に決定的な検出器ではない——旧モデルが生成した、あるいは大幅に編集・言い換え・翻訳・他の文章と混合されたテキストは検出できない場合がある。

## ベストプラクティス

- プラットフォーム側で検証 API を組み込む際は「陽性は信頼、陰性は不定」でポリシー設計する。「透かし未検出」を「人間の創作」の証拠にしない。
- 自前の生成サービスの出力には C2PA 資格情報を積極的に付与する——低コストで、コンプライアンスのトレンド方向。
