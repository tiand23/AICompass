# A2A

## 概要

A2A（Agent-to-Agent Protocol）：Google 主導のエージェント間連携オープンプロトコル——メッセージ形式・タスク調整・能力発見を標準化し、独立に開発されたエージェント同士がタスクを委任し合えるようにする。50+ ベンダーが支持（Salesforce、MongoDB、ServiceNow など）、エージェント間決済を扱う拡張 **AP2**（Agent Payments Protocol）もある。

## なぜ重要か

複雑なビジネスは単一エージェントでは支えられず、マルチエージェント連携には横方向の標準が必要——A2A はこの層のリーダー。MCP と構成する「二層プロトコルスタック」（MCP 縦・A2A 横）が企業デプロイのアーキテクチャデフォルトになりつつあり、プロトコルへの投資はエコシステム相互運用性への投資。

## コアコンセプト

- **Agent Card / 能力発見**：エージェントが自分の能力を標準形式で宣言し、他のエージェントがそれを発見して委任する。
- **タスクライフサイクル**：エージェント間タスクの提出・進行・成果物受け渡しに統一された状態セマンティクス。長時間タスクにも対応。
- **MCP と補完関係**：個々のエージェントは MCP でツールを呼び、複数エージェントは A2A で調整する——本番システムは通常両方を併用。
- **AP2 決済拡張**：エージェント間の安全な取引のためのプロトコル層——エージェント経済のインフラの原型。

## ベストプラクティス

- 組織内のマルチエージェントはまずフレームワーク内蔵のオーケストレーション（同一プロセス/プラットフォーム）で。A2A の真価は組織・ベンダーの境界を越えるところにある——プロトコルのためのプロトコル採用はしない。
