# Voice Agents

## 概要

音声エージェント：音声をインターフェースとするリアルタイム対話エージェント——音声カスタマーサポート、音声アシスタント、面接/研修対話などのシナリオを支える技術形態。2 つの技術路線が並存する：**カスケード式**（STT → LLM → TTS、各段を独立に選定可能）と**エンドツーエンドのリアルタイム音声モデル**（speech-to-speech、OpenAI GPT-Live など。聞きながら話す）。代表フレームワーク：livekit/agents、Pipecat。

## なぜ重要か

音声はカスタマーサポート、面接、車載、アクセシビリティなどの自然なインターフェースであり、エージェントがエンタープライズ CX に浸透する主経路でもある。テキストエージェントとの本質的な違いは**リアルタイム性**：レイテンシ、割り込み、ターンテイキングが「人間らしさ」を直接決める——この工学・評価のレイヤーはテキストエージェントには存在しない。2026 年にリアルタイム音声モデル（GPT-Live 系）が商用化され、音声エージェントは「会話できる」から「体験で競う」段階に入った。

## コアコンセプト

- **カスケード vs エンドツーエンド**：カスケード式（STT→LLM→TTS）は柔軟・制御可能・各段のベンダー交換可能だが、レイテンシが累積し語気情報が失われる；エンドツーエンドの speech-to-speech は低レイテンシでパラ言語情報（語気・間）を保持するが、制御性とツール呼び出しの成熟度はまだ追い上げ段階。
- **レイテンシ予算**：人間の会話の自然な応答間隔は約 200-800ms；カスケードパイプラインではストリーミング STT、LLM の first token、ストリーミング TTS の 3 段でレイテンシを削る必要がある。
- **割り込み処理（barge-in）とターン検出**：ユーザーはいつでも割り込む——エージェントは即座に止まり、会話を拾い直せなければならない。VAD/ターン検出の精度が会話の流暢さを直接決める。
- **3 軸評価**（LangChain、2026-08 提唱）：実行（ツール呼び出し/プロセスの正しさ）、成果（ビジネス達成）、体験（レイテンシ/割り込み/自然さ）——音声特有なのは第 3 軸。
- **接続チャネル**：WebRTC（ブラウザ/アプリ）と電話（SIP/PSTN）が 2 大チャネルで、フレームワーク層（livekit など）が差異を吸収する。
- **重み公開のローカル TTS**：カスケード式の STT/LLM/TTS 3 工程のうち、TTS はこれまでクラウドの商用 API に依存することが多かった；重みが公開され完全にセルフホストできる TTS（NVIDIA Magpie TTS など）は、カスケードルート全工程のローカル化における最後のピースを埋める——レイテンシやデータコンプライアンスに敏感なシナリオでは、エンドツーエンド音声モデルより「制御性優先」の志向に合致する選択肢だ。

## ベストプラクティス

- 路線選定はシナリオの「制御可能性」要件から：プロセスとコンプライアンスが厳しいサポートはカスケード（各段が監査可能でフォールバックあり）、体験優先のアシスタント系はエンドツーエンドも選択肢。
- 対話品質だけを評価しない——レイテンシ分布（P50/P95）、割り込み復帰成功率を受け入れ指標に入れる。
