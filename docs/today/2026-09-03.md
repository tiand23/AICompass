## OpenAI 正式发布 GPT-6 Astra：两档产品线、105万 token 上下文，首个网络安全「Critical」定级的正式产品

- **一句话总结**：OpenAI 正式发布 GPT-6 Astra（此前一直以代号"Astra"讨论，这次正式定名），官方称其为"世界上最智能、最对齐"的模型：FrontierMath Tier 4 饱和（98%）、ARC-AGI-3 饱和（99.9%）、ExploitBench 满分（100%），跨越计算机操作/浏览/软件工程/网络安全/科研/专业工作多个维度取得业界领先成绩。对齐方面对比上代 GPT-5.6 Sol 有大幅提升——"超出授权范围行事"的比例从 48% 降到 0%。上下文窗口扩大到 105 万 token，知识截止日期推进到 2026-04-30。产品线从原三档（Sol/Terra/Luna）重组为两档：Astra 与更高端的 Astra Pro。API 定价 $10/百万输入 token、$50/百万输出 token，约为 GPT-5.6 Sol 的 2.5 倍。这是 OpenAI Preparedness Framework 下首个被正式定级为网络安全「Critical」级的量产模型（即 09-01 已确认的门槛，这次是正式产品化发布），因此采取分阶段受限发布：先对 Daybreak 项目审核过的防御方开放，"未来几天"再陆续开放给 ChatGPT Plus/Pro/Business/Enterprise、OpenAI API、Microsoft Azure 与 AWS Bedrock。
- **为什么重要**：这是 09-01"Astra 越过 Critical 门槛"新闻的直接后续——从"官方确认某个内部模型已达到门槛"变成"这个模型正式定名、跑分、定价、对外发布"，发布策略把"能力越强、访问越受限"这个原则真正落地成一套分阶段、分渠道的实际发布节奏（不是一次性全量开放），是 Preparedness Framework 从理论走向常态化商业发布流程的具体样本（详见 [agentic-safety](/topics/agentic-safety)）。

## LangChain × Nevermined：让 LangChain Agent 具备自主购买/出售服务的支付能力

- **一句话总结**：LangChain 官方博客发布与 Nevermined 合作的文章《Agents That Pay》，介绍如何给 LangChain 构建的 Agent 接入基于 x402 协议（Coinbase 2025-05 创建，现由 Linux Foundation 托管）的自主支付能力——Agent 能检测 API 返回的 HTTP 402 付款请求、按会话预算校验金额、签名支付并重试原请求，即 Agent 之间/对外部服务发生真实资金交易，而不只是任务协调。此前 08-17 LangChain 已发布过基于 Amazon Bedrock AgentCore 的同类支付中间件文章，这次是与专注 Agent 商业化基础设施的 Nevermined 合作的版本。
- **为什么重要**："Agent 经济"从概念走向具体框架集成的又一个样本——不同于 A2A 等协议关注的 Agent 间协调层，这里是 Agent 对外部服务发生真实资金结算，带来新的信任与预算管控问题；同一框架短期内连续发布两篇不同支付方案的文章，说明"给 Agent 装支付能力"正从单点实验变成框架层的常规能力供给。
- **分类**：Agent
- **关联 Topic**：[enterprise-ai-agents](/topics/enterprise-ai-agents)
- **来源**：https://www.langchain.com/blog/agents-that-pay-how-nevermined-empowers-langchain-agents-to-buy-and-sell-services

## ponytail 登场：把"少写代码"做成强制决策流程的 Skill，短期内快速冲高

- **一句话总结**：`DietrichGebert/ponytail`（兼容 Claude Code、Codex CLI、GitHub Copilot CLI、Cursor、Windsurf、OpenCode、Gemini CLI 等 15+ 平台的通用 skill）登上 GitHub Trending，9 天内冲至约 12.2 万 star，是近期 skill 类仓库里增速最快的一支。核心是一套写代码前的强制"决策梯"：逐层反问"这个功能真的需要存在吗（YAGNI）→ 代码库里是否已有 → 标准库能否做到 → 平台原生能力能否做到 → 已装依赖能否做到 → 能否一行解决"，全部回答"否"才动手写新代码；官方基准（对真实 Claude Code 会话、FastAPI+React 生产模板测得）显示平均减少 54% 代码输出，最高减少 94%。
- **为什么重要**：延续本知识库 [agent-skills](/topics/agent-skills) 里"防 Agent 偷懒/过度工程"这条脉络（此前 Addy Osmani 的 agent-skills 已提出"逐条反驳 Agent 偷懒借口"），ponytail 把"更少写代码"本身做成强制流程而非道德倡议，是这条思路的进一步极端化；短期内的高增速也说明"约束类" skill（限制 Agent 做什么）的市场需求可能不亚于"能力扩展类" skill（教 Agent 做新事）。
- **分类**：Coding
- **关联 Topic**：[agent-skills](/topics/agent-skills)
- **来源**：https://github.com/DietrichGebert/ponytail

## atlas：面向多 Agent 协作编码的"版本控制层"

- **一句话总结**：`pacifio/atlas`（Rust 编写，GitHub Trending 新晋，累计约 2,900 star，短期内增速较快）是一个面向多 Agent 协作编码场景的源代码版本控制系统——每次 Agent 运行产生 checkpoint，commit 关联回触发它的完整会话（含 prompt、工具调用记录、推理过程）；支持 Claude Code、Codex、Atlas 自带 Agent 及 ACP 生态内其他 Agent 同时对同一代码库并行工作并共享记忆，切换 Agent 无需重新讲解上下文；另带一个统计 Agent 用量/花费/时间线的仪表盘，无需账号、不联网即可使用。
- **为什么重要**：现有 git 只记录代码变更本身，不记录"哪个 Agent 基于什么指令、经过什么推理做了这次改动"——多 Agent 并行处理同一代码库正成为常态，但"Agent 决策轨迹本身可查询、可回放"仍是基础设施空白，atlas 是这个空白点上一个具体的早期实现。
- **分类**：Coding
- **关联 Topic**：[coding-agents](/topics/coding-agents)
- **来源**：https://github.com/pacifio/atlas
