# 2026-10-07

## Claude Haiku 5.5 发布；Sonnet 5.5 缓存读取价再降；Managed Agents 新增反数据泄露的 URL 溯源限制

- **一句话总结**：Anthropic 发布 Claude Haiku 5.5：100 万 token 上下文、12.8 万最大输出、effort 参数驱动的自适应思考，经 Claude API、Amazon Bedrock、AWS/Google Cloud 上的 Claude Platform、Microsoft Foundry 同步提供；从 Haiku 4.5 迁移的破坏性变更——手工指定思考预算（`budget_tokens`）的扩展思考方式返回 400 错误，自适应思考默认开启、回复可能以 `thinking` 块开头，同样文本计入更多 token。同日 Claude Sonnet 5.5 的缓存读取价从每百万 token $0.20 降到 $0.10（相当于基础输入价的 0.05 倍，此前是 0.1 倍）；Python/TypeScript SDK 新增浏览器与计算机使用工具的 beta 封装类（自动跑工具循环、URL/文件策略、审批回调）；Max/Team 订阅新增每月 API 额度。Claude Managed Agents 一次上线三项网络限制加固：`limited` 网络模式下 `web_search`/`web_fetch` 新增 `allowed_hosts` 白名单（超出范围返回 `url_not_allowed`）；创建会话时若 `allowed_domains` 超出 `allowed_hosts` 范围直接 400 拒绝；`web_fetch` 现在只能抓取"本次会话中已经出现过"的 URL——来自 Claude 自己输出、系统提示词、附件文档、工具输出里的 URL 一概拒绝（返回 `url_not_in_prior_context`），把能抓取的网址限定到用户消息原文中出现过的那些，直接针对数据泄露风险。
- **为什么重要**：Haiku 5.5 补齐 Opus/Sonnet 5.5（09-22/09-28）之后 Claude 模型线三档的同代际升级，三款模型在一个月内全部完成换代；`web_fetch` 的"仅抓取会话中已出现过的 URL"是一个具体、可推广的反数据泄露设计模式——把"能不能抓某个 URL"从"是否在白名单里"进一步收紧到"用户是不是真的提到过这个地址"，直接切断了"提示注入在工具输出里塞一个恶意 URL 诱导 Agent 外发数据"这条常见攻击路径。
- **分类**：Models
- **关联Topic**：[claude-models](/topics/claude-models)・[agentic-safety](/topics/agentic-safety)
- **来源**：https://platform.claude.com/docs/en/release-notes/overview

## LangChain 发布 Managed Deep Agents v0.9（定时任务/按次运行配置/Slack 反应）与 Deep Agents Skills 重构

- **一句话总结**：LangSmith Managed Deep Agents v0.9 公测新增：Schedules SDK，用户通过聊天创建/修改/查看/删除定时任务——"周期任务"把一个 prompt 和 cron 调度规则绑定，"一次性任务"则在指定时间运行并把结果回复到原线程（如"一小时后检查部署状态"）；按次运行配置让同一个部署可以依据运行时上下文选择不同的模型/指令/skills/工具/沙箱（例如财务频道走计费相关 skill、平台团队走故障响应工具，而不必为每种场景复制粘贴一个几乎一样的 Agent）；Slack 确认反应（默认 👀，可关闭或换成其他 emoji）也开放配置。同日 LangChain 发文《Revamping Skills in Deep Agents》重构 Skills 机制：企业 skill 库规模涨到数千条后暴露三个问题——工具与 skill 披露分离导致 Agent 可能绕过指令直接用工具、显式请求的 skill 仍要多一轮模型调用才能加载、长时程线程无法在不重启的情况下感知新增/修改的 skill；三项具体改动——`include_tools` 让 skill 在元数据里绑定工具（工具对上下文保持隐藏直到 Agent 读取该 skill，才作为新系统消息出现，支持中途加工具的模型可借此保持 prompt 缓存不失效）、`pinned_skills` 让应用在模型调用前把指定 skill 的完整指令直接预加载进对话（省掉"先发现再加载"这一轮）、调用时把 `skills_metadata` 设为 `None` 可让缓存的 skill 列表失效，使长时程线程不重启也能感知到新/改过的 skill；整体仍保持"渐进式披露"（Agent 先只看到 skill 名称，按需加载详情）这一核心设计原则不变。
- **为什么重要**：Managed Deep Agents v0.9 紧接两周前的 v0.8（新认证/记忆/消息渠道）与三周前的 Connections（托管凭证），托管运行时能力扩充的节奏明显在加快；Skills 重构则是 skill 生态规模化到"企业级数千条"后首次系统性解决"工具披露与 skill 披露脱节""长时程线程感知不到 skill 更新"这两个此前被忽视的工程问题，对已经把 skill 库做大的团队有直接参考价值。
- **分类**：Agent
- **关联Topic**：[deep-agents](/topics/deep-agents)
- **来源**：https://www.langchain.com/blog/revamping-skills-in-deep-agents

## LlamaIndex 发布 OpenDocRouter：多文档解析模型统一 API

- **一句话总结**：LlamaIndex 发布 OpenDocRouter——把前沿模型（Claude Opus 5.5、GPT-6 Luna、Gemini 3.8 Flash）与开源模型（MinerU2.5-Pro、TeleOCR、PaddleOCR-VL）统一到一个 API 之下做文档转 Markdown，单接口支持 PDF/PNG/JPEG/URL、最多 500 页或 50MB；`layout: True` 可输出带定位边界框与阅读顺序的版式元素，不同模型的输出被标准化为一致的版式类别；支持同步（最多 50 页）与异步两种调用方式；按 token 计费，起步 $25 额度，每千页成本 $0.86～$48.82（视模型选择）。
- **为什么重要**：定位为比 LlamaParse 更轻量的替代方案——不是自建一个更强的解析模型，而是把"管理多个文档模型的 prompt 适配、限速、部署、成本优化"这件麻烦事统一包装成一个路由层，让开发者能快速在最新模型间切换试验而只为实际用量付费，呼应了 08-31 Cohere Parse V5"成本是独立可选的选型维度"这一趋势的进一步产品化。
- **分类**：RAG
- **关联Topic**：[document-parsing](/topics/document-parsing)
- **来源**：https://www.llamaindex.ai/blog/introducing-opendocrouter

## LiquidAI 开源 d1-3B / d1-omni-600M：单次前向传播输出确定性答案的端侧决策模型

- **一句话总结**：LiquidAI 发布 d1 决策模型家族的开放权重版本——d1-3B 与实验性的多模态 d1-omni-600M（同时支持文本+图像、文本+音频）；与常规生成式 Transformer 逐 token 输出不同，d1 系列用单次前向传播直接给出确定性答案；d1-3B 综合得分 82.9，超过 Decider 4B 基线，d1-omni-600M 得分 78.4，以四分之一参数量超过 Decider 2B；桌面 GPU 上单次查询 10 毫秒内完成、处理 384 像素图像 18 毫秒内完成，NVIDIA Jetson 等端侧设备上 50 毫秒内完成；权重开放在 HuggingFace 可本地下载。
- **为什么重要**：与同日的 OpenAI Decisions API、此前的 LangChain Jev 共同构成"决策/判定类任务拆分成独立模型品类"这一新趋势在端侧场景的样本——把"要不要生成文本"这件事本身去掉，用单次前向传播直接出确定性答案，是这条趋势里走得最远的架构选择（详见 [model-efficiency](/topics/model-efficiency) ・ [agent-evaluation](/topics/agent-evaluation)）。
- **分类**：Models
- **关联Topic**：[model-efficiency](/topics/model-efficiency)・[agent-evaluation](/topics/agent-evaluation)
- **来源**：https://www.liquid.ai/blog/d1-open
