## OpenAI DevDay 2026：Dots 常驻 Agent、GPT-6.1 Sol、Pro 500/Ultrafast、ChatGPT Space 与 Private Intelligence

- **一句话总结**：OpenAI DevDay 2026 一次性发布 20 余项更新，核心包括：**Dots**——7×24 小时常驻运行的 Agent，拥有自己的电脑与浏览器、可接入 4000+ 生态应用、从反馈中持续学习，由 Astra 驱动，包含在 Pro 订阅内且不占用额度；**GPT-6.1 Sol**——GPT-6 Sol 的升级版，在编码/计算机使用/专业工作上的智能接近 Astra，标准输入输出定价仅为 Astra 的五分之一；**Pro 500**——$500/月新订阅档，提供 25 倍于 Plus 的用量额度并包含 Ultrafast 速度档；**Ultrafast**——付费速度档，官方称 Codex 中 token 生成最高提速 8 倍、API 中提速 6 倍；**ChatGPT Space**——把 Pages（面向人与 Agent 共同编辑的新文档形态）、文件、项目上下文、团队成员与 AI Agent 整合进同一个共享工作空间；**OpenAI Private Intelligence**——数据零留存的 Private Safety Processing 现已可用，具备机密计算能力的 Private Inference 将于今秋晚些时候预览。
- **为什么重要**：这是 OpenAI 继 09-03 GPT-6 Astra 正式发布之后一个月内最大规模的平台级更新——Dots 把"常驻自主 Agent"做成默认订阅内功能而非独立产品，GPT-6.1 Sol 延续"旗舰模型能力下放到工作机型、价格大幅下降"的节奏（类似此前 Luna/Terra 降价），ChatGPT Space + Pages 则是把"人机协作文档"产品化——三条线合起来勾勒出 OpenAI 把 Agent 自主性、低成本工作模型、协作文档整合进统一工作空间的路线图。

## H Company 开源 Holo4：通用计算机使用 Agent 模型，GUI/代码/MCP 自主切换

- **一句话总结**：H Company 在 HuggingFace 发布 Holo4 权重（27B 稠密与 35B-A3B MoE 两种规格，另有更小的 Holotron4 Nano），由 H Company 自家 Agentic Task Factory 生成的大规模环境/任务数据监督+强化学习训练；单一模型自主决定每一步该用哪种界面——点击/输入屏幕、编写并运行代码、调用 MCP 或 API 工具；OSWorld 2.0 基准上 Holo4 27B 得分 61.7%（对比 Claude Opus 5.5 的 81.8%），35B-A3B 得分 30.9%，但参数量级低一到两个数量级、成本远低。权重以 BF16/FP8/NVFP4/4-bit GGUF 等多种精度开放。
- **为什么重要**：是开源计算机使用 Agent 模型向"单模型自主判断用哪种接口完成任务"（而非固定走 GUI 或固定走代码）演进的一个具体样本，用大幅落后旗舰闭源模型的分数换取开放权重与低成本部署，延续"专用小模型用更小代价覆盖垂直能力"的效率路线。
- **分类**：Agent
- **关联Topic**：[coding-agents](/topics/coding-agents)
- **来源**：https://huggingface.co/blog/Hcompany/holo4

## 研究提出 ProvenanceGuard：针对 MCP Agent 的"溯源感知"事实核查

- **一句话总结**：论文《ProvenanceGuard: Source-Aware Factuality Verification for MCP-Based LLM Agents》指出现有事实核查方法（RAGAS faithfulness、MiniCheck、AlignScore、SummaC 等）只判断"某个论断是否被证据池里的某处证据支持"，不判断"这段输出引用的具体来源是否真的支持它"——这类"跨来源混淆"错误（论断在证据池某处为真，但被错误地归到了答案所指的来源）会被传统核查方法放过；ProvenanceGuard 消费带稳定工具 ID/来源 ID/原始输出的 MCP 调用记录，把答案拆解成原子论断，把每条论断路由到对应来源的证据，用 NLI 加 token 对齐做支持度核查，再比对"声称的来源"与"实际路由到的来源"是否一致，输出逐条论断判定与整体放行/拦截结论。
- **为什么重要**：MCP 让 Agent 可以一次调用多个工具/数据源拼接答案，但目前主流事实核查方法并不关心"引用对不对源"，这个盲区会随着 MCP Agent 普及而放大——ProvenanceGuard 是第一个把"溯源正确性"作为独立核查维度系统化的方案（详见 [mcp](/topics/mcp)）。
- **分类**：Evaluation
- **关联Topic**：[mcp](/topics/mcp)・[agent-evaluation](/topics/agent-evaluation)
- **来源**：https://huggingface.co/blog/MultiverseComputingCAI/getting-the-source-right-not-just-the-fact-source
