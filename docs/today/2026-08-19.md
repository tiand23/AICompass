## OpenAI 预览 Private Safety Processing：不破坏 Zero Data Retention 的跨交互滥用检测

- **一句话总结**：OpenAI 宣布正在与早期客户测试 Private Safety Processing——一套在保留 Zero Data Retention（零数据留存，ZDR）承诺的前提下、跨多次相关交互识别滥用模式的安全监控系统。设计动机是解决现有 ZDR 兼容安全系统的一个局限：这些系统只能孤立评估单次交互，而随着模型承接更长、更自主的任务，一些严重风险（如被诱导执行的长程恶意任务）只有跨越多轮交互才会显现。新系统只向 OpenAI 侧发送一个窄范围界定的"安全信号"（例如"疑似滥用"标记），不暴露底层 prompt 或响应内容本身；客户数据既可以留在客户自己控制的基础设施上，也可以由 OpenAI 存储但加密密钥由客户掌握。目前面向符合条件的企业与 API 客户开放测试，不含消费级 ChatGPT 订阅用户；更广泛的上线与技术白皮书计划于 9 月发布。
- **为什么重要**：这是"隐私保护"与"安全监控"这对此前被视为此消彼长的目标，在架构层面找到具体折中方案的一个实例——此前 ZDR 的代价通常是安全团队对交互内容的可见性归零，Private Safety Processing 试图证明"不留存原始内容"与"跨交互发现滥用模式"可以同时成立，关键在于把粒度从"内容"降到"窄范围信号"。对于把长程自主任务交给 Agent 执行的企业客户，这类跨会话行为监控能力，本质上是"EDR for Agents"这条本知识库持续追踪的安全工具链叙事，从被动的运行时检测（如 Uber ADR）向由模型厂商自己在推理侧提供的托管能力延伸的又一例证；报道也将其解读为对 Anthropic 现有合规日志留存要求的一种差异化竞争。

## Claude 平台 Agent Skills API 转正式 GA；Managed Agents 新增网络工具域名白名单/黑名单

- **一句话总结**：Claude Platform Release Notes 公布一批 API 转正式 GA（无需 beta header）：①**Agent Skills 与 Skills API**（`/v1/skills`）正式 GA，包括通过 `container` 参数在 Messages API 里加载 Skill 的请求；②Files API（`/v1/files`）正式 GA，含文件过期与分页机制；③Claude Enterprise 组织的 Admin API 用户管理端点（成员、邀请、群组、自定义角色）正式 GA。同批还新增一项 Managed Agents 安全控制：可以为一个 agent 的 `web_search`/`web_fetch` 工具设置 `allowed_domains` 或 `blocked_domains`，`web_fetch` 另支持 `max_content_tokens` 限制抓取内容长度、`web_search` 支持 `user_location`。所有变更均向后兼容——仍带旧 beta header 的请求继续按原格式工作。
- **为什么重要**：Skills API 从 beta 转正式 GA，标志着自 2025 年 10 月推出以来快速扩张的 Skill 生态（本知识库持续追踪的"生态热度"排行已有十余个高星第三方仓库）终于有了官方 API 层面的生产级承诺，第三方工具与企业集成不必再担心 beta header 随时变化。Managed Agents 的域名白名单/黑名单则是"权限最小化"原则在托管 Agent 网络访问场景的具体落地——此前该原则多体现在工具调用权限与凭证注入层面，这次把控制粒度下沉到"Agent 可以联网访问哪些具体域名"，是托管 Agent 安全配置项持续细化的又一例。
- **分类**：Agent
- **关联 Topic**：[agent-skills](/topics/agent-skills) ・ [cloud-agent-platforms](/topics/cloud-agent-platforms)
- **来源**：https://platform.claude.com/docs/en/release-notes/overview
