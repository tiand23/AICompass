## LlamaIndex 论证：文档 OCR 不会被前沿模型商品化

- **一句话总结**：LlamaIndex 发文《Document OCR is Not Getting Commoditized》：ParseBench 数据显示专用解析引擎仍领先 GPT-5.5 约 20 分且成本更低；前沿模型的视觉定位（spatial grounding）能力仅约 8%，专用引擎达 55-80%；且各实验室的后训练算力都投向数学/代码/Agent，文档阅读不在优先级上（GPT-5 system card 与 Gemini 3 发布说明均未提文档解析改进）。
- **为什么重要**：直接回应"等大模型更强就不需要专用解析器了"这一常见选型判断——空间定位的差距是结构性的：Agent 需要知道数据出自哪一页哪个位置，证据链依赖它；四种"蒸馏策略"（按复杂度路由、专项 RL 后训练、利用 PDF 文本层/OOXML 原生元数据、闭环评估）让专用引擎的优势可持续。注意 ParseBench 是 LlamaIndex 自家基准，论点带立场，但结构性论据值得纳入长期判断。
- **分类**：RAG
- **关联 Topic**：[document-parsing](/topics/document-parsing)
- **来源**：https://www.llamaindex.ai/blog/document-ocr-is-not-getting-commoditized

## Uber 开源 ADR：企业级 AI Agent 检测与响应系统

- **一句话总结**：Uber 开源 ADR（Agentic AI Detection and Response）——已在 Uber 生产环境部署的 Agent 安全系统：Sensor 采集 7+ 编码 Agent（Claude Code/Cursor/Codex 等）在 macOS/Linux/Windows 上的意图、工具调用与执行轨迹；ADR-Bench 用 300+ 任务与 133 个 MCP server 构建安全基准；检测采用两层架构（高召回分诊 + 对可疑会话的深度 agentic 推理）；阻断模块未开源。论文入选 MLSys 2026。
- **为什么重要**："EDR for Agents"这一品类出现了——把终端安全的"检测与响应"范式搬到 Agent 行为上，且出自大厂生产实践而非安全厂商概念稿；ADR-Bench 还是首个把 MCP server 当作攻击面系统化测试的基准。至此 Agent 安全工具链三块拼图齐了：治理（agent-governance-toolkit）、评估透明（Anthropic 红队复盘）、运行时检测（ADR）。

## video-use 登上 GitHub Trending：用编码 Agent 剪视频，靠转写而非吃帧省 token

- **一句话总结**：browser-use 团队发布 video-use（累计 19.5k star）单日 +320——让 Claude Code 等编码 Agent 用自然语言剪辑视频：去除填充词/静音、调色、卡点音频淡入淡出、烧字幕、生成动画叠加层，并在每个剪辑点自渲染自评估。关键设计是不让模型直接吃视频帧（token 爆炸），而是先用 ElevenLabs Scribe 把音频转成带词级时间戳的文字稿（约 12KB），只在必要时才用文件带/波形图的 PNG 合成图做视觉分析；管线为 转写→打包→LLM 推理→EDL→渲染→自评估。
- **为什么重要**：这是"用文字稿代理视觉信息、按需才动用视觉"这一多模态省 token 模式在视频剪辑场景的落地——与文档解析里的"按复杂度路由到不同解析器"是同一思路的跨领域复现：先把高维信号压缩成低维代理表示，模型主要在压缩表示上推理，真正需要像素级信息时才局部升维。
- **分类**：Coding
- **关联 Topic**：[coding-agents](/topics/coding-agents)
- **来源**：https://github.com/browser-use/video-use

## Claude 上线 Inference Hooks：推理前置的企业级实时策略网关

- **一句话总结**：Claude Enterprise 新增 Inference Hooks（beta）：每一条受管辖的 prompt（覆盖 claude.ai、Cowork、Claude Code 全部界面）在真正推理前先同步 POST 给企业自建的"AI 安全服务器"，等待 allow/deny 裁决（默认 5 秒超时），裁决通过 Standard Webhooks 规范签名；deny 时用户看不到模型回复，只看到策略拒绝提示；服务器只能看到用户能看到的内容（文字、工具调用与结果、附件抽取文本），拿不到系统提示词或原始文件字节；可先用影子模式/按比例灰度上线，不必上来就全量拦截。
- **为什么重要**：这是"模型推理"第一次被官方开放为**可插入策略网关的一个环节**，而不只是事后审计——此前 Claude 的 Compliance API 只能秋后算账，Inference Hooks 把 DLP、模型白名单、工作时间限制这类规则做到了推理前实时拦截。结合前一天 Uber 开源的 ADR（事中/事后行为检测），企业 Agent 安全正在补齐"事前拦截—事中检测—事后审计"的完整链路。目前该能力只覆盖 claude.ai/Cowork/Claude Code，Bedrock/Vertex 渠道与 Platform API 不在范围内。
- **分类**：其他（安全）
- **关联 Topic**：[agentic-safety](/topics/agentic-safety) ・ [claude-models](/topics/claude-models)
- **来源**：https://platform.claude.com/docs/en/manage-claude/inference-hooks

## LangChain 发布 Kubernetes 自治 SRE Agent 案例：读自主、写必须过人

- **一句话总结**：LangChain 发文详解基于 Deep Agents 构建的 Kubernetes 自治 SRE Agent：调度器做轻量周期健康检查（纯 Python + 单次 Haiku 调用），触发异常后并行拉起多个专项子 Agent（pod-inspector、scaling-analyzer、log-analyzer、security-auditor 等）深入排查，Sonnet 驱动的编排器汇总诊断并通过 Slack 提出修复建议，但执行模块严格锁死在人工审批之后——设计铁律是"读是自主的，写永远经人工把关（HITL）"，且审批范围刻意收窄，不允许 Helm 升级这类大范围高影响命令一键通过。
- **为什么重要**：这是"分层用模型控成本"（便宜模型做高频轻量检查、贵模型只在需要深度推理时介入）与"读写权限分离"两条原则在真实运维场景的联合示范；对准备把 Agent 用于基础设施运维、又担心自动化"跑飞"的团队，这是一份可以直接照抄的架构范式——尤其是"审批范围要窄到人能看懂"这一条，比"要有人工审批"这种空泛建议更可落地。
- **分类**：Agent
- **关联 Topic**：[deep-agents](/topics/deep-agents) ・ [enterprise-ai-agents](/topics/enterprise-ai-agents)
- **来源**：https://www.langchain.com/blog/how-we-build-an-autonomous-sre-agent-for-kubernetes-deployments
