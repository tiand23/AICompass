## Firecrawl 开源 pdf-inspector：文档解析的"第一道分诊"组件

- **一句话总结**：pdf-inspector（Rust）单日 +1,699 star（累计 8.2k）——Firecrawl 开源的轻量 PDF 检测库：10-50ms 内把 PDF 分类为文本型/扫描型/图像型/混合型（带置信度，靠采样页面的内容流分析文本/图像算子），免 OCR 做位置感知的文本抽取并转干净 Markdown（含表格检测、多语言编码），支持 WASM 浏览器本地运行，带 Python/Node 绑定。
- **为什么重要**：文档解析管线的"第一道分诊"被做成了专用组件——先毫秒级判断 PDF 类型，再路由到 OCR 或直接文本抽取，与 LlamaIndex Parse Gateway 的页面级路由是同一趋势的不同粒度；WASM 支持意味着分诊可以完全在端侧完成，敏感文档不必出本地。
- **分类**：RAG
- **关联 Topic**：[document-parsing](/topics/document-parsing)
- **来源**：https://github.com/firecrawl/pdf-inspector

## DeepSeek-Reasonix 登上 Trending：终端编码 Agent 按模型生态分化

- **一句话总结**：DeepSeek-Reasonix（Go）连续两日 Trending（单日 +883，累计 29.9k）——DeepSeek 原生的终端编码 Agent：单一静态 Go 二进制，provider/agent/工具/插件全部在 `reasonix.toml` 里声明的配置驱动架构；围绕 DeepSeek prefix cache 调优上下文管理（保持缓存稳定、修剪过期工具输出）压长会话成本；插件经 stdio JSON-RPC 子进程运行（兼容 MCP），任意 OpenAI 兼容端点可接。
- **为什么重要**：终端编码 Agent 已是独立品类，且开始按模型生态分化——Claude Code 之后出现"DeepSeek 原生"的对位物；针对特定模型的成本结构（prefix cache）做 harness 级调优是新的差异化维度，单二进制 + 配置驱动则代表了这类工具的极简架构取向。
- **分类**：Coding
- **关联 Topic**：[coding-agents](/topics/coding-agents)
- **来源**：https://github.com/esengine/DeepSeek-Reasonix

## LangChain 发布语音 Agent 评测方法论：执行・结果・体验三轴

- **一句话总结**：LangChain 发文《How to evaluate voice agents》，提出语音 Agent 的三轴评测框架：执行（工具调用与流程正确性）、结果（业务目标达成）、体验（延迟、打断处理、对话自然度等语音特有指标）。
- **为什么重要**：语音 Agent 比文本 Agent 多出一整层"体验轴"——延迟预算、turn-taking、打断恢复这些实时性指标在文本评测里不存在；GPT-Live 等实时语音模型商用后，这类方法论补位是必然动作，三轴框架可以直接搬进语音客服/面试类项目的验收标准。
- **分类**：Evaluation
- **关联 Topic**：[agent-evaluation](/topics/agent-evaluation) ・ [voice-agents](/topics/voice-agents)
- **来源**：https://www.langchain.com/blog/how-to-evaluate-voice-agents-execution-outcomes-and-experience
