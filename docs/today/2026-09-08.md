## LangChain 提出 Deep Agents 多 Agent 协作的"上下文模式"：Forked vs Isolated Subagents

- **一句话总结**：LangChain 为 Deep Agents 框架新增 `'mode': 'fork'` 上下文模式——子 Agent 启动时继承主管（supervisor）当前的完整状态与对话历史（借助 prompt 缓存复用），区别于默认的 Isolated 模式（子 Agent 只拿任务描述，从空白上下文起步）；给出选型准则：Worker Agent 用 fork、Verifier/Researcher 用 isolated、Memory Agent 用 fork。
- **为什么重要**：Supervisor/子 Agent 架构里，子 Agent 空白起步常常要把主管已经做过的取证工作（如读文件）重新做一遍，白白浪费算力与时间；显式区分两种上下文传递模式，把这个取舍从"隐式默认"变成"按角色显式选型"的工程决策。
- **分类**：Agent
- **关联 Topic**：[deep-agents](/topics/deep-agents)
- **来源**：https://www.langchain.com/blog/organizing-context-in-a-multi-agent-harness

## Microsoft 发布 Discovery Engine 与 CLIO：多路径推理驱动的科学发现 Agent

- **一句话总结**：Azure AI 发布 Microsoft Discovery Engine，内核为 CLIO（Cognitive Loop via In-Situ Optimization）——多条独立推理路径并行探索问题、互相比对与共享中间发现，收敛为一个有证据支撑的结果，且可自主决定继续探索、切换策略、换用其他模型或引入人类领域专家；在 "Agent's Last Exam" 基准上取得健康/医学 61.6%、物理科学 75.2%、生命科学 64.6%，并称已协助发现一种新型有机氧化还原液流电池。
- **为什么重要**：这是"长时程 Agent 遇到不确定性时该怎么办"（继续探索 / 换策略 / 换模型 / 叫人）这一 Deep Agents 核心难题，在垂直科研领域的一次具体产品化实现，且给出了可比较的基准分数而非纯概念宣传。
- **分类**：Agent
- **关联 Topic**：[deep-agents](/topics/deep-agents)・[enterprise-ai-agents](/topics/enterprise-ai-agents)
- **来源**：https://azure.microsoft.com/en-us/blog/beyond-the-benchmark-how-an-adaptive-approach-drives-scientific-discovery/
