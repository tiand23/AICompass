## Cloudflare 开源 computer：给 Agent 一台可编程的"电脑"

- **一句话总结**：Cloudflare 开源 computer（单日 +891，累计 2,900 star）——运行在 Durable Object 内的虚拟文件系统（状态存 SQLite），配三种可插拔执行后端：Container（把状态映射成真实 FUSE 挂载，完整 Linux 用户态+网络访问）、Isolate Shell（Dynamic Worker 里跑 just-bash，经 Workers RPC 访问工作区）、Isolate JavaScript（在全新 Dynamic Worker 里执行 ES 模块）。统一入口 `workspace.runtime.exec()`，工作区可脱离具体后端独立工作。目前明确标注"仅预览，尚不适合生产"。
- **为什么重要**：这是 E2B/Daytona 一类"Agent 沙箱即服务"思路的云厂商自研版，且把"文件系统状态"和"执行后端"解耦成了两层——同一份工作区状态可以按需切换成真实容器、隔离 shell 或纯 JS 沙箱，而不是绑死一种隔离强度。对架构判断的启发是：Agent 执行环境的"存储层"和"隔离层"本该是两个独立可替换的组件，而不是像多数沙箱产品那样打包死。
- **分类**：Agent
- **关联 Topic**：[agent-sandboxes](/topics/agent-sandboxes)
- **来源**：https://github.com/cloudflare/computer

## loopx 登场：长时程 Agent 团队的"状态内核"

- **一句话总结**：huangruiteng/loopx（单日 +326，累计 2.1k star）——不替代 Agent 运行时本身，而是给 Codex/Claude Code/Cursor 等任意 Agent 加一层本地控制平面："agent 原生的看板"：持久目标（Durable Goals）跨多轮多会话存活、可认领可交接的可执行待办（Executable Todos）、按配额决定继续/求助人类/等待/停止（Quota-Aware Scheduling）、留存决策与验证记录的证据日志、带类型的可验证交接（Verifiable Handoffs）。
- **为什么重要**：它精准命中了长时程多 Agent 协作的一个真实缺口——聊天界面天然不适合承载"目标会漂移、责任会转手、证据会过期、成本在无声堆积"这类跨会话状态；loopx 不做另一个 Agent 框架，而是做 Agent-agnostic 的外部状态管理层，这个"运行时之外单独立一层状态内核"的设计取向，值得和 AIDD 的 Staging Area + 证据链思路对照着看——本质都是"给自主执行加一层可审计的持久状态"。
- **分类**：Agent
- **关联 Topic**：[deep-agents](/topics/deep-agents)
- **来源**：https://github.com/huangruiteng/loopx

## Addy Osmani 发布 agent-skills：把专业工程纪律打包成 24 个 Skill

- **一句话总结**：Addy Osmani（前 Google Chrome 团队、《Learning JavaScript Design Patterns》作者）发布 agent-skills（单日 +226，累计 8.2 万 star）——24 个 skill 模块覆盖开发全生命周期（Define/Plan/Build/Verify/Review/Ship），每个 skill 都带分步流程、验证要求，以及专门列出"Agent 可能会用来偷懒跳步的常见借口"并逐条堵上；配 8 个斜杠命令（`/spec`、`/plan`、`/build`、`/test`、`/review`、`/webperf`、`/code-simplify`、`/ship`）和 4 个专家人格（代码评审、测试工程师、安全审计、性能审计），已支持 70+ 编码 Agent 客户端安装。

## LangChain 发文厘清 Deep Agents / LangChain / LangGraph 三者关系

- **一句话总结**：LangChain 官方给出三者的定位区分：Deep Agents 是带开箱即用最佳实践的"有主见"Agent harness（内置文件系统后端、子 Agent、skills、记忆管理）；LangChain 是"LLM 在循环里调用工具"的极简框架，用 middleware hook 做定制；LangGraph 是基于图的 Agent 运行时，能把领域知识直接编码进图拓扑而非全靠模型临场判断，追求最大确定性。三者可组合，都能经 LangSmith 部署——本质是同一套技术栈里，"能动性（灵活）↔确定性（可靠）"这条光谱上的三个刻度。
- **为什么重要**：这是 LangChain 首次系统性回答"我该用你们家哪个"这个高频困惑，给出的选择原则很具体：复杂长任务、要开箱即用的上下文管理选 Deep Agents；需要精确控制每一步给模型喂什么工具和上下文选 LangChain；流程不是标准循环、需要混合确定性步骤与自主步骤时选 LangGraph。对正在用 LangGraph 做企业级工作流的团队，这份定位说明也间接回答了"什么时候该收窄到图、什么时候可以放权给 Agent 自主判断"这个架构决策。
- **分类**：Agent
- **关联 Topic**：[agent-frameworks](/topics/agent-frameworks) ・ [deep-agents](/topics/deep-agents)
- **来源**：https://www.langchain.com/blog/deep-agents-vs-langchain-vs-langgraph

## OpenAI 公布 Astra 内部版数学成果：27 年无人解开的猜想被形式化证明

- **一句话总结**：OpenAI 正式确认下一代旗舰模型代号 **Astra**，并发布 249 页手稿：Astra 内部版本解决了群论、高维几何、量子复杂度、格密码学、极值组合等 5 个以上数学领域里合计 10 个悬而未决十年以上的公开问题，全部产出可机器验证的 Lean 4 形式化证明，GitHub 仓库"sorry"计数为零（即全部证明步骤无遗留未验证部分）；总计算成本约 2000 美元。头条结果是**首次给出非苏芬群（non-sofic group）的显式构造**——这是 1999 年提出、27 年来无人类数学家解开的问题。手稿与证明证书以 Apache 2.0 协议开源。Astra 本身未公布发布日期与定价，且必须先通过美国政府安全审查才能对外提供。
- **为什么重要**：这是"AI 做数学"从"能通过竞赛题基准"跃升到"能产出人类 27 年未解开的开放问题的形式化证明"的一次质变——机器可验证证明（Lean 4，sorry 计数零）意味着结果不依赖对模型输出的信任，可独立复核，这是比"模型在 XX 榜单拿了高分"扎实得多的能力证据。对模型选型和技术趋势判断而言，这标志着前沿模型的推理能力开始真正触及人类专家能力的边界，而"必须过政府安全审查才能发布"这一条件本身也是模型能力已达到需要国家层面管控考量的信号。

## Claude Code 上线自托管执行环境公测：会话可以直接跑在企业自己的网络里

- **一句话总结**：Anthropic 为 Claude Code 推出自托管环境（Self-Hosted Environments）公测：Team/Enterprise 计划组织可以把会话跑在自己的基础设施上而非 Anthropic 托管服务器——从网页、移动端、桌面、终端或定时任务发起的会话统一路由进组织自己的网络内，紧邻内部服务、工具链与安全管控。架构上由长驻的 runner 进程接单并派生独立 Claude Code 进程，支持固定数量 runner 与按需自动扩缩容（编排器按排队情况动态启停 runner）两种模式；每个会话跑在隔离的 checkout 里，避免开发者之间互相干扰。仓库检出、构建产物、生成文件都留在客户基础设施上；但对话内容与 prompt 仍需传给 Anthropic 做推理，会话转录会远程存储以支持跨端续接——即"执行本地化"而非"完全本地化"。默认关闭，需自建 runner 镜像与编排、自行承担运维；不支持零数据留存（ZDR）客户。
- **为什么重要**：这是同一天 Cloudflare computer 展示的"存储层与执行层解耦"思路，在头部厂商自家旗舰编码 Agent 上的落地——Claude Code 的执行环境（runner）与云端推理服务（模型本身）被拆成两层，前者可以放进客户网络，后者仍留在 Anthropic 侧。这精确对应了企业侧"源码不能出内网、但愿意让 prompt/对话内容经过供应商推理"这一常见合规红线，是比"要么全托管、要么完全自建"更细粒度的第三条路。同时官方坦诚说明"仍需自建 runner 镜像与编排"这一运维成本，是对"自托管=零成本解决合规"这类过度乐观预期的一次务实纠偏。
- **分类**：Agent
- **关联 Topic**：[coding-agents](/topics/coding-agents) ・ [enterprise-ai-agents](/topics/enterprise-ai-agents)
- **来源**：https://claude.com/blog/run-claude-code-sessions-on-your-own-compute
