## Microsoft 提出"Agent 优先平台"架构：治理与执行环境分离

- **一句话总结**：Microsoft Foundry 发文主张 Agent 应用需要与传统应用不同的基础设施假设——传统应用响应用户请求，Agent 则在循环里持续自主行动，把 Agent 跑在共享基础设施上会带来安全与管控风险；给出的架构方案是把治理（Microsoft Foundry）与执行环境（Azure Container Apps Sandboxes）分离，让 Agent 在按秒创建、任务结束即销毁的硬件级隔离 microVM 里以限定权限运行，既限制故障/越权的影响半径又保留监督能力。文中给出三个案例：毕马威（KPMG）同时运行超过 3 万个 Azure Container Apps Sandboxes；Cognite Atlas AI 把数天的调查工作压缩成"可追溯、分钟级交付的答案"；南澳大利亚教育系统因此省掉约 5 万行自建代码解释器状态管理代码。
- **为什么重要**：这是"给 Agent 一台自己的计算机而非一堆工具"（08-11 monday.com Sidekick 案例）这条思路在基础设施架构层面的系统化表述，并首次把"治理面"与"执行面"分离作为 Agent 平台设计的显式原则提出，附带三个量化规模的生产案例佐证。
