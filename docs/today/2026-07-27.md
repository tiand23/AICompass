## NVIDIA 联合 36 家企业发起 Open Secure AI Alliance：OpenAI/Google/Anthropic/Meta 集体缺席（补漏）

- **一句话总结**：NVIDIA 联合 Microsoft、Cisco、Cloudflare、CrowdStrike、HuggingFace、IBM、Palo Alto Networks、Red Hat、Elastic、SpaceXAI 及 Linux Foundation 等共 37 家机构发起 Open Secure AI Alliance，目标是"开发并共享用于加固软件与 AI Agent 安全的开放技术、方法与工具"；联盟的核心主张是网络安全防御方需要"能读、能改、能在自己硬件上跑"的模型，而不能只依赖通过厂商 API 才能触达的闭源系统。联盟首个技术产出是 NOOA（NVIDIA-labs OO Agents）框架——Apache 2.0 协议的研究框架，把 Agent harness 表示成 Python 类：方法体写成省略号（`...`）的部分在运行时由 LLM 驱动的循环去"补全"，标准 Python 方法则保持确定性执行；在 CyberGym L1 基准上跑出 86.8% 的成绩，但仓库自己明确声明其抽象语法树检查与模块拒绝列表只是"纵深防御的一层控制"，"不是隔离边界"。值得注意的是，OpenAI、Google、Meta、Anthropic 均不在首批成员名单中——尽管这几家刚在 7 月 24 日联署过一份行业政策联名信；联盟材料没有说明这几家缺席的原因、是否在洽谈加入、或加入需要贡献什么。联盟本身也缺少章程、理事会、具体技术工作组、交付时间表或共享代码仓库，Linux Foundation 的角色仅是提供一个竞争对手之间协作的中立场所，而非正式治理架构。此次结盟直接回应 7 月 HuggingFace 遭入侵事件（详见 07-21 ExploitGym 记录）：攻击者通过一个滥用远程代码数据集加载器、在数据集配置里做模板注入的恶意数据集，逐步实现节点访问、凭证窃取与内网横向移动。HuggingFace 事后用开放权重的 GLM 5.2 分析了 17,000 多条记录的攻击行为、复原完整攻击时间线——原因是商用闭源前沿模型 API 的安全过滤器一开始直接拒绝了分析所需的攻击指令、漏洞利用载荷与 C2（命令控制）相关内容的请求。但报道也澄清：开放模型只是帮助复原了入侵过程、支持了事后响应，并不代表 GLM 5.2 独立检测、阻止或遏制了这次入侵。
- **为什么重要**：这是围绕 ExploitGym/HuggingFace 入侵事件的产业级集体回应，也是"开放权重模型"这场争论里一个此前被忽视的具体论据——商用闭源模型的安全护栏在事后取证这种合法防御场景里同样会拦截"看起来像攻击"的请求，说明"护栏严格程度"和"防御能力"之间不是单调递增关系，安全从业者做威胁分析本身也需要能读改自己模型的能力。头部大模型厂商集体缺席这一联盟同样值得记录——一边是这几家联署行业政策信呼吁"步调机制"，一边是网络安全防御的实际行动上明显没有参与由硬件厂商与安全公司主导的开放技术联盟，这种"公开表态"与"具体行动"的错位，是判断行业实际治理进展时值得持续关注的信号。NOOA 框架"确定性代码与 LLM 驱动代码混合、且明确承认自己的检查只是纵深防御而非隔离边界"的坦诚表述，也是 Agent 安全工具自我定位趋于务实、不过度承诺的一个例子。
- **分类**：其他（安全）
- **关联 Topic**：[agentic-safety](/topics/agentic-safety)
- **来源**：https://thehackernews.com/2026/07/nvidia-forms-37-member-open-secure-ai.html
