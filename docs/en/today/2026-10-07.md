# 2026-10-07

## Claude Haiku 5.5 launches; Sonnet 5.5 prompt-cache reads get cheaper; Managed Agents add anti-exfiltration URL provenance checks

- **Summary**: Anthropic launches Claude Haiku 5.5: 1M-token context window, 128K max output, adaptive thinking driven by the effort parameter, available simultaneously via the Claude API, Amazon Bedrock, Claude Platform on AWS/Google Cloud, and Microsoft Foundry. Breaking changes migrating from Haiku 4.5: manually specifying a thinking budget (`budget_tokens`) via extended thinking now returns a 400 error, adaptive thinking is on by default and responses may start with a `thinking` block, and the same text now counts as more tokens. The same day, Claude Sonnet 5.5's prompt-cache read price drops from $0.20 to $0.10 per million tokens (0.05x the base input price, down from 0.1x); the Python/TypeScript SDKs add beta wrapper classes for the browser-use and computer-use tools (handling the tool loop, URL/file policy, and approval callbacks automatically); Max/Team subscriptions gain monthly API credits. Claude Managed Agents ship three network-hardening changes at once: `limited` networking mode adds an `allowed_hosts` allowlist to `web_search`/`web_fetch` (returning `url_not_allowed` outside it); session creation now rejects (400) if `allowed_domains` falls outside `allowed_hosts`; and `web_fetch` now only fetches URLs that have already appeared in the current session — URLs from Claude's own output, the system prompt, attached documents, or tool output are all rejected (`url_not_in_prior_context`), narrowing fetchable URLs to those that actually appeared in the user's own message text, directly targeting data-exfiltration risk.
- **Why it matters**: Haiku 5.5 completes the same-generation 5.5 refresh across all three Claude tiers, following Opus and Sonnet (09-22/09-28) — all three model tiers finish their generational turnover within a single month. The `web_fetch` restriction to "only URLs that already appeared in the session" is a concrete, generalizable anti-exfiltration design pattern — tightening "can this URL be fetched" from "is it allowlisted" to "did the user actually mention this address," directly cutting off the common attack path where prompt injection plants a malicious URL in tool output to lure the agent into exfiltrating data.

## LangChain launches Managed Deep Agents v0.9 (schedules/per-run config/Slack reactions) and a Deep Agents Skills overhaul

- **Summary**: LangSmith Managed Deep Agents v0.9 public beta adds: a Schedules SDK letting users create/modify/list/delete scheduled tasks through chat — a recurring task pairs a prompt with a cron schedule, while a one-time task runs at a specified time and replies in the original thread (e.g. "check the deployment status in an hour"); per-run configuration, letting one deployment choose its model/instructions/skills/connected tools/sandbox based on runtime context (e.g. billing skills in a finance channel, incident-response tools for a platform team, without copy-pasting near-identical agents for each scenario); and configurable Slack acknowledgment reactions (default 👀, can be disabled or swapped). The same day, LangChain publishes "Revamping Skills in Deep Agents," overhauling how Skills work: as enterprise skill libraries grew to thousands of skills, three problems emerged — tools being disclosed separately from skills let an agent bypass the instructions and use a tool directly; skills requiring an extra round trip to load even when explicitly requested; and long-running threads being unable to pick up newly added or modified skills without restarting. Three concrete fixes: `include_tools` lets a skill bind tools in its metadata (hidden from context until the agent reads that skill, then arriving as a new system message — on models that accept new tools mid-conversation, this keeps the prompt cache intact); `pinned_skills` lets an application preload a named skill's full instructions into the conversation before the model call, skipping the "discover, then load" round trip; and setting `skills_metadata` to `None` at invocation invalidates the cached skill list, letting a long-running thread pick up new or changed skills without starting over — all while preserving the framework's core "progressive disclosure" principle.
- **Why it matters**: Managed Deep Agents v0.9 follows v0.8 (new auth/memory/channels) from two weeks ago and Connections from three weeks ago — the pace of hosted-runtime capability expansion is clearly accelerating. The Skills overhaul is the first systematic fix, once a skill library scales to enterprise thousands, for two previously overlooked engineering problems — tool disclosure decoupled from skill disclosure, and long-running threads blind to skill updates — directly useful for any team that has already scaled up a skill library.
- **Category**: Agent
- **Related Topic**: [deep-agents](/en/topics/deep-agents)
- **Source**: https://www.langchain.com/blog/revamping-skills-in-deep-agents

## LlamaIndex launches OpenDocRouter: a unified API across document-parsing models

- **Summary**: LlamaIndex launches OpenDocRouter, unifying frontier models (Claude Opus 5.5, GPT-6 Luna, Gemini 3.8 Flash) and open-source ones (MinerU2.5-Pro, TeleOCR, PaddleOCR-VL) behind a single API for document-to-Markdown conversion — one endpoint handling PDF/PNG/JPEG/URL inputs up to 500 pages or 50MB; setting `layout: True` returns Markdown with grounded bounding boxes and layout elements in reading order, standardized into consistent layout classes regardless of the underlying model's native capability; both synchronous (up to 50 pages) and asynchronous requests are supported; pricing is token-based, starting at $25 in credits, with cost ranging $0.86-$48.82 per 1,000 pages depending on model choice.
- **Why it matters**: Positioned as a lighter-weight alternative to LlamaParse — rather than building a stronger parsing model itself, it packages the hassle of managing prompting, rate limits, deployment, and cost optimization across multiple document models into one routing layer, letting developers rapidly experiment across the latest models while paying only for what they use, extending the 08-31 Cohere Parse V5 trend of "cost as an independent selection dimension" into a product.
- **Category**: RAG
- **Related Topic**: [document-parsing](/en/topics/document-parsing)
- **Source**: https://www.llamaindex.ai/blog/introducing-opendocrouter

## LiquidAI open-sources d1-3B / d1-omni-600M: edge decision models that output deterministic answers in a single forward pass

- **Summary**: LiquidAI releases open weights for its d1 decision-model family — d1-3B and the experimental multimodal d1-omni-600M (supporting text+image and text+audio); unlike conventional generative transformers producing tokens sequentially, d1 models return a deterministic answer in a single forward pass. d1-3B scores a mean of 82.9, beating the Decider 4B baseline, while d1-omni-600M scores 78.4, beating Decider 2B with a quarter of the parameters; on desktop GPUs, d1-3B resolves a single query in under 10ms and a 384-pixel image in under 18ms, and under 50ms on edge devices like NVIDIA Jetson; weights are published on Hugging Face for local download.
- **Why it matters**: Together with the same week's OpenAI Decisions API and the earlier LangChain Jev, this is an edge-focused instance of "decision-making splitting off into its own specialized model category" — dropping the idea of generating text at all and outputting a deterministic answer in one forward pass is the most extreme architectural choice in this trend so far (see [model-efficiency](/en/topics/model-efficiency) ・ [agent-evaluation](/en/topics/agent-evaluation)).
