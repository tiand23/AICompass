## code-review-graph Arrives: Tree-sitter Code Graphs Give AI Tools "Lineage Analysis" to Save Tokens

- **Summary**: tirth8205/code-review-graph (+237 stars in a day, 29k total) — uses Tree-sitter to parse a codebase's functions, classes, imports and call relationships into a directed graph, stored locally in SQLite (`.code-review-graph/`); when code changes, it runs blast-radius analysis to trace affected callers, dependents and tests; AI tools query the graph through 30 MCP tools instead of reading the whole file tree. Measured result: reviewing the Flask codebase costs 143,594 tokens naively but only 2,196 with the graph — a **71x** reduction; across six real repos the median per-question saving is about **65x**. Supports incremental updates (re-indexing a 3,000-file project in ~2.5 seconds), 40+ languages, a GitHub Action for risk-scored PR review, optional vector semantic search, and Leiden-algorithm community detection.
- **Why it matters**: A concrete, data-backed implementation of "build a code structure graph for AI tools to save tokens" — essentially the third recurrence of the same pattern seen in document parsing's "spatial grounding" and video editing's "transcribe-to-proxy": compress high-dimensional raw information (the entire codebase's text) into a structured, low-dimensional proxy representation (the call graph), reason mainly on the proxy, and expand to source-level detail locally only when truly needed. MCP as the graph's query interface is another instance of "expose structured knowledge via a protocol, not a text dump."
- **Category**: Coding
- **Related Topic**: [ai-code-review](/en/topics/ai-code-review) ・ [coding-agents](/en/topics/coding-agents)
- **Source**: https://github.com/tirth8205/code-review-graph

## Claude Managed Agents Ships Four Enterprise Ops Features at Once: Budget Caps, Advisor Models, Data Residency, GitHub-Loaded Skills

- **Summary**: Claude Managed Agents shipped four features the same day: ① Session Budgets — a hard cap on a session's spend (priced at public list rates); a session that hits its budget pauses with `budget_reached` instead of starting new model requests, and changing or removing the budget resumes it. ② Advisor — give a session's primary thread a "advisor" model at least as capable as the agent's own to consult mid-turn for strategic guidance. ③ `inference_geo` — set where model inference runs per agent or per session, for data-residency compliance. ④ Skills can now be loaded directly from a mounted GitHub repository — any skills in its root `.claude/skills` directory are auto-discovered at session start.
- **Why it matters**: Taken together, these complete the "cost control + reliable decisions + compliance control + pluggable capability" set that enterprises need from a hosted agent runtime. The Advisor design is especially notable — it doesn't replace execution with a stronger model, but lets that model act as a mid-turn strategic consultant to the primary thread, a new implementation of the cost-layering idea "spend the expensive model's budget only on the expensive part — judgment." Loading skills directly from a mounted GitHub repo also means skill updates and code-repo version control share a single source, with no separate distribution channel to maintain.

## Anthropic Sharply Narrows Fable 5's Biology False Positives: Down ~85%

- **Summary**: Anthropic rewrote Fable 5's biology-safety classifier "constitution" (the rule set distinguishing restricted from allowed content), added detailed carve-outs for benign uses, gathered expert feedback, and retrained the classifier on updated training data — the result: biology-related fallbacks (false-positive blocks) dropped by roughly 85%, letting the model assist with a much broader range of legitimate biology work. Requests in virology, toxicology and molecular design are still blocked and routed to the less-capable Opus 5; a trusted-access pathway for frontier biology research remains in development.
- **Why it matters**: A concrete case of "dual-use safeguards" moving from blanket restriction to fine-grained calibration — Fable 5 launched with broad limits given its standout biology capability, and this update shows the safety team is genuinely feeding real usage data back into the classifier rather than setting a guardrail and walking away. For developers building in biomedicine, chemistry and other sensitive domains, previously-blocked legitimate requests are worth retrying; it also signals a repeatable methodology — guardrail precision comes from "rule refinement + data feedback," not simply loosening a threshold.

## LangSmith Ships Managed Deep Agents Public Beta: A Hosted Runtime for Deep Agents

- **Summary**: LangSmith launched Managed Deep Agents in public beta — turning the open-source Deep Agents framework into a hosted service: develop and debug locally with `mda dev`, deploy to the LangSmith-hosted runtime with `mda deploy`. It provides durable execution (long tasks pause/retry/resume without losing state), streaming progress and state persistence, sandboxes (isolated file-work and code-execution environments via LangSmith Sandboxes), agent-scoped memory persisting across conversations, native Slack/GitHub channels, OIDC-backed identity with per-user thread scoping, Harbor-framework eval integration, and full LangSmith tracing. Currently limited to LangSmith Cloud (US region), CLI-first, no pricing announced.
- **Why it matters**: Deep Agents itself stays open-source and model-agnostic for self-hosting; the Managed version packages the operational infrastructure — durable execution, sandboxes, memory, observability — that teams previously had to assemble themselves into an opinionated, ready-to-use hosted runtime. It's another instance of the "platform provides the base, business provides the capabilities" division of labor recurring throughout this knowledge base, and a natural extension of the LangChain ecosystem from "open-source Deep Agents framework" to "hosted Deep Agents runtime" — the third vendor, after Claude Managed Agents and Gemini API Managed Agents, to formally launch "hosted deep agents" as a product line.

## Claude Code v2.1.224: Sessions Can Now Message Each Other — From a Single-Session Tool to a Small Distributed System

- **Summary**: Claude Code 2.1.224 adds cross-session communication: independent Claude Code sessions can discover each other and exchange plain-text messages via two tools, `ListAgents` and `SendMessage` — a message is defined strictly as "a piece of text one Claude writes to another," never conversation history or files. Same-machine sessions communicate over Unix domain sockets; cross-machine sessions route through Anthropic's Remote Control infrastructure. The following day's 2.1.225 further loosened the restriction, letting a session proactively initiate a conversation with a named Remote Control session rather than only replying. macOS/Linux only for now. This complements the self-hosted runners shipped the day before (see 08-06): runners solve where execution happens, cross-session messaging solves how multiple independent sessions coordinate.
- **Why it matters**: This is a key step moving Claude Code from "one person, one terminal session" toward "multiple sessions coordinating autonomously" — previously, multi-agent coordination relied either on an external orchestration framework (LangGraph-style) or an external state layer (loopx-style); Claude Code now builds the most basic capability — discovering peers and exchanging messages — directly into the product itself. The design choice to strictly limit messages to "plain text, no history, no files" is also worth noting — it avoids the risk surface of context/credential leakage across sessions, trading minimal information bandwidth for cross-session coordination, a concrete instance of least-privilege applied to multi-agent communication.
- **Category**: Agent
- **Related Topic**: [coding-agents](/en/topics/coding-agents) ・ [deep-agents](/en/topics/deep-agents)
- **Source**: https://code.claude.com/docs/en/whats-new/2026-w32
