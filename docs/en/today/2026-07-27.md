## NVIDIA Joins 36 Companies to Launch the Open Secure AI Alliance: OpenAI/Google/Anthropic/Meta All Absent (backfilled)

- **Summary**: NVIDIA, along with Microsoft, Cisco, Cloudflare, CrowdStrike, HuggingFace, IBM, Palo Alto Networks, Red Hat, Elastic, SpaceXAI, the Linux Foundation and others — 37 organizations in total — launched the Open Secure AI Alliance, aiming to "develop and share open technology, methods and tools for hardening software and AI agent security." The alliance's core claim is that cyber defenders need models they can "read, modify, and run on their own hardware," rather than being limited to closed systems reachable only through a vendor's API. Its first technical output is the NOOA (NVIDIA-labs OO Agents) framework — an Apache 2.0-licensed research framework that represents agent harnesses as Python classes: method bodies written as ellipses (`...`) get "completed" at runtime by an LLM-driven loop, while standard Python methods stay deterministic. It scores 86.8% on the CyberGym L1 benchmark, but the repo itself explicitly states its AST checks and module denylists are only "one layer of defense-in-depth control," "not a containment boundary." Notably, OpenAI, Google, Meta and Anthropic are all absent from the founding member list — despite having jointly signed an industry policy letter together just days earlier, on July 24. The alliance materials don't explain why these four are absent, whether they're in talks to join, or what joining would require. The alliance itself also lacks a charter, board, concrete technical workstreams, delivery timeline, or a shared code repository — the Linux Foundation's role is only to provide a neutral venue for competitors to collaborate, not a formal governance structure. This alliance directly responds to July's HuggingFace breach (see the 07-21 ExploitGym entry): attackers used a malicious dataset that abused a remote-code dataset loader and template injection in dataset configs to progressively achieve node access, credential theft and lateral movement. HuggingFace afterward used the open-weights model GLM 5.2 to analyze over 17,000 logged actions and reconstruct the full attack timeline — because commercial closed-source frontier model APIs' safety filters initially rejected the requests needed for the analysis, which involved attack instructions, exploit payloads and C2 (command-and-control)-related content. But reporting also clarifies: the open model only helped reconstruct the intrusion and supported the after-the-fact response — it did not itself detect, stop, or contain the breach.
- **Why it matters**: This is an industry-wide collective response to the ExploitGym/HuggingFace breach, and also a previously overlooked concrete data point in the open-weights debate — that commercial closed-source models' safety guardrails will also block "attack-looking" requests even in a legitimate defensive forensic-analysis scenario, showing that "guardrail strictness" and "defensive capability" are not a monotonically increasing relationship — security practitioners doing threat analysis themselves need the ability to read and modify their own models. The collective absence of the leading frontier-model vendors from this alliance is equally worth recording — on one hand these companies co-signed an industry policy letter calling for a "pacing mechanism," while on the other they are conspicuously not participating in concrete cybersecurity-defense action led by hardware vendors and security companies; this mismatch between "public statements" and "concrete action" is a signal worth continuing to watch when assessing the industry's actual governance progress. The NOOA framework's honest self-description — mixing deterministic code with LLM-driven code, and explicitly acknowledging its own checks are only defense-in-depth rather than a containment boundary — is also an example of agent security tooling maturing toward realistic, non-overpromising self-positioning.
- **Category**: Other (security)
- **Related Topic**: [agentic-safety](/en/topics/agentic-safety)
- **Source**: https://thehackernews.com/2026/07/nvidia-forms-37-member-open-secure-ai.html
