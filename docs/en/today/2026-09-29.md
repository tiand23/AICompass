## H Company open-sources Holo4: a generalist computer-use agent model that switches autonomously between GUI, code, and MCP

- **Summary**: H Company publishes Holo4 weights on Hugging Face (27B dense and 35B-A3B MoE variants, plus the smaller Holotron4 Nano), trained via supervised and reinforcement learning on large-scale environment/task data generated by H Company's own Agentic Task Factory; a single model decides on its own, at each step, which interface to use — clicking/typing on screen, writing and running its own code, or calling MCP/API tools. On OSWorld 2.0, Holo4 27B scores 61.7% (versus 81.8% for Claude Opus 5.5) and the 35B-A3B variant scores 30.9%, achieving this with one to two orders of magnitude fewer parameters and much lower cost. Weights are published in BF16, FP8, NVFP4, and 4-bit GGUF.
- **Why it matters**: This is a concrete example of open computer-use agent models evolving toward "a single model autonomously decides which interface fits the task" (rather than hardcoding GUI or code paths), trading a large score gap versus flagship closed models for open weights and low-cost deployment — continuing the "a smaller, cheaper specialist model can cover a vertical capability" efficiency trend.

## Research proposes ProvenanceGuard: "source-aware" fact-checking for MCP agents

- **Summary**: The paper "ProvenanceGuard: Source-Aware Factuality Verification for MCP-Based LLM Agents" points out that existing fact-checking methods (RAGAS faithfulness, MiniCheck, AlignScore, SummaC, etc.) only ask "is this claim supported somewhere in the pooled evidence," not "does the output's cited source actually support it." This "cross-source conflation" failure — a claim that's true somewhere in the evidence pool but attributed to the wrong source — slips past traditional checkers. ProvenanceGuard consumes captured MCP traces with stable tool IDs, source IDs, and raw outputs; decomposes answers into atomic claims; routes each claim to its specific source evidence; checks support via NLI plus a token-alignment proxy; compares the claimed attribution against the routed source; and returns per-claim verdicts plus an overall allow/block decision.
- **Why it matters**: MCP lets an agent stitch together an answer from multiple tool/data-source calls in one go, but mainstream fact-checking methods today don't care whether a citation points to the right source — a blind spot that will grow as MCP agents spread. ProvenanceGuard is the first approach to systematize "is the attribution correct" as its own independent verification dimension (see [mcp](/en/topics/mcp)).
- **Category**: Evaluation
- **Related Topic**: [mcp](/en/topics/mcp)・[agent-evaluation](/en/topics/agent-evaluation)
- **Source**: https://huggingface.co/blog/MultiverseComputingCAI/getting-the-source-right-not-just-the-fact-source
