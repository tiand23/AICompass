## Tencent Cloud Open-Sources TencentDB-Agent-Memory: A Team-Level Agent Memory Hub

- **Summary**: TencentDB-Agent-Memory (TypeScript) gained +602 stars in a day (11k total) — it turns conversations, documents and code into four types of reusable memory assets: layered Chat Memory (L0 raw conversations → L3 personas), Skills extracted from agent interactions (versioned, shared after team review), structured Wiki (with link graphs), and CodeGraph indexing code symbols and call relationships. Assets carry RBAC visibility (private/team/restricted/agent) and bind to specific agents as loadouts rather than global injection; integrations include OpenClaw and hermes-agent.
- **Why it matters**: Agent memory is upgrading from "one user's session context" to "a team-shared asset layer" — the four asset types (memory/skills/knowledge/code graph) amount to a complete reference architecture for memory infrastructure. And "auto-extract skills from interactions, share after review" pulls skill production into the memory pipeline: the memory and capability ecosystems are starting to converge.

## Agent-Reach Hits GitHub Trending: A CLI Capability Layer That Gives Agents "Internet Reach"

- **Summary**: Agent-Reach (Python) gained +659 stars in a day (64.7k total) — no per-platform API keys; it lets agents read and search X, Reddit, YouTube, GitHub, Bilibili, XiaoHongShu, Instagram, LinkedIn, RSS and the web. It reuses mature CLI tools (yt-dlp, Jina Reader, …; some services via MCP), gives each platform a primary method plus a fallback list, and switches automatically when a route breaks; compatible with Claude Code, Cursor and other clients that can execute CLIs.
- **Why it matters**: An engineering route complementary to MCP's protocol standardization — no protocol wrappers, just reuse of existing CLI tools plus health checks and fallback routing, addressing the operational reality that anti-scraping measures and API churn break tools daily. The "agents reaching content platforms" layer is getting properly engineered.

## Stripe Builds "Kai", Its Company-Wide Agent, on Deep Agents

- **Summary**: LangChain published the Stripe case study: company-wide productivity agent "Kai" (connected to internal data warehouses, Slack and Google Suite, generating reports/dashboards that evolve alongside conversations) — one engineer built the first version in a week on Deep Agents, with a Stripe-specific harness and a configuration layer on top. Key design: three middlewares (virtual S3-backed filesystem, sandboxed execution, context summarization) plus a federated skills model (individual teams own 1,000+ skills covering 500+ internal tools, dynamically loaded to prevent context overload). Users grew 16x to 5,000+ within four weeks of preview; today 83% of Stripe uses Kai weekly across 60,000+ sessions.
- **Why it matters**: The most complete "company-wide general agent" production case to date, validating three things: the open-source-harness-plus-your-own-layers architecture is viable with tiny startup cost (one person, one week); the filesystem/sandbox/summarization middleware combo is the standard kit for long-session agents; and skills federated to business teams — rather than centrally produced by the platform team — is what covers the long tail of internal tools.
