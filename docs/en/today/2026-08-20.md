# 2026-08-20

## Claude Python SDK Reaches v1.0: Migrates from httpx to httpx2, Removes Several Long-Deprecated Interfaces

- **Summary**: Anthropic released Claude Python SDK v1.0: the HTTP layer moves from `httpx` to `httpx2`, a maintained API-compatible fork (libraries that patch httpx for tracing/mocking need to call `httpx2.alias_httpx()`); requires Python 3.10+; removes long-deprecated surface including the legacy Text Completions API, the `temperature`/`top_p`/`top_k` parameters on Messages methods, and the tool runner's client-side `compaction_control`; the async client's `.with_raw_response` results now need `await response.parse()`; `AnthropicBedrock` now raises an error rather than defaulting to `us-east-1` when no region is configured. A full migration guide is provided.
- **Why it matters**: A textbook "clear the debt" major release — everything removed was already deprecated for a long time, so users following current usage patterns will barely notice, but integrations still on old versions, patching httpx, or missing a configured region need to work through the migration guide item by item — a genuinely breaking change (see [claude-models](/en/topics/claude-models)).
- **Category**: Agent
- **Related Topic**: [claude-models](/en/topics/claude-models)
- **Source**: https://platform.claude.com/docs/en/release-notes/overview

## LangSmith Launches Preview Builds Public Beta: Auto-Generated Agent Preview Deployments per PR

- **Summary**: LangSmith Preview Builds public beta: opening a PR automatically creates an isolated preview deployment linked to production, rebuilding automatically and staying in sync as new commits land — giving teams (including non-engineering roles like product, domain experts and QA) a "PR-specific artifact" they can directly access and test, without standing up a full production deployment for every PR. Supports "every PR" or "label only" triggering; previews inherit the parent deployment's secrets, with configurable idle TTL and max concurrent previews. Available only for deployments using the GitHub integration on LangSmith Cloud; pricing not disclosed during beta.
- **Why it matters**: This systematically brings the mature web-dev practice of "CI/CD preview environments" into agent deployment — previously agent changes were either tested locally or verified directly in production, and now there's a collaborative middle ground; it also brings non-engineering roles into the "can just click and test" review loop (see [enterprise-ai-agents](/en/topics/enterprise-ai-agents)).
- **Category**: Agent
- **Related Topic**: [enterprise-ai-agents](/en/topics/enterprise-ai-agents)
- **Source**: https://www.langchain.com/blog/langsmith-preview-builds-test-agent-changes-before-production

## LiquidAI Releases LFM2.5-DSpark: Speculative-Decoding Draft Models, Up to 3.18x Faster Inference

- **Summary**: Liquid AI released LFM2.5-DSpark — speculative-decoding draft models (~300M parameters) for the LFM2.5 line (2.6B/1.2B-Instruct/8B-A1B), combining a DFlash-style parallel backbone, a lightweight sequential head (modeling Markov dependencies between adjacent tokens to boost acceptance rate), and a confidence-scheduled verifier (pruning low-confidence suffixes when verification cost exceeds the benefit). Achieves 2.1-2.67x average speedup on H100 (peak 3.18x on MATH500), 1.18-2.54x on-device speedup on an M4 Max MacBook, and a 57% average cut in function-calling latency; output matches the greedy-decoding baseline token-for-token, with no quality loss. Already supported in llama.cpp (with Metal kernels) and SGLang.
- **Why it matters**: Complements the same batch's QAD (the quantization route, covered 08-19) — one preserves accuracy through more precise quantization, the other through a draft model that better understands the target model's behavior; together the two routes cover the main approaches to making edge models faster without losing quality (see [model-efficiency](/en/topics/model-efficiency)).
- **Category**: Models
- **Related Topic**: [model-efficiency](/en/topics/model-efficiency)
- **Source**: https://huggingface.co/blog/LiquidAI/lfm25-dspark
