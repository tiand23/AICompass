## OpenAI Retires Atlas Browser, Folds "Browser Agent" Capability into ChatGPT and Codex

- **Summary**: OpenAI announced that Atlas (launched 2025-10-21, an independent browser built around ChatGPT with an Agent-mode preview) stops working on 2026-08-09, and advised users to export bookmarks and other important data beforehand. In its place, OpenAI is applying what it learned from Atlas to strengthen ChatGPT's own browser experience — multiple tabs, downloads, improved navigation, account login support — with deeper agentic browser work directed to the ChatGPT desktop app; browser-agent capability is folding into Codex as well.
- **Why it matters**: A case where the "standalone browser agent product" route proved less economical than "embedding agent capability into an existing flagship product" within less than a year — similar to the earlier retirement of platform-layer products like Agent Builder, another instance of the standalone-new-form-product survival risk this knowledge base has repeatedly flagged for OpenAI, confirming the behavioral pattern of "OpenAI's platform-layer products get deprecated fast; core capability converges into ChatGPT/Codex." Developers who integrated with Atlas's Agent mode or browser-automation interfaces need to plan a migration path to the equivalent ChatGPT/Codex capabilities.
- **Category**: Agent

- **Source**: https://help.openai.com/en/articles/20001371-evolving-atlas-into-chatgpt-for-browser-based-agentic-work

## Harvey Open-Sources Harvey LAB, a Legal Agent Benchmark: 24 Practice Areas, 1,671 Real Tasks

- **Summary**: Legal AI company Harvey open-sourced Harvey LAB (695 stars total, +47/day) — a benchmark for evaluating LLM agents on legal work in realistic environments: a dataset of agent instructions, documents and rubrics, paired with an execution harness. It covers 24 legal practice areas (contracting especially), 1,671 tasks including realistic M&A data-room assignments, scored via all-pass rubrics plus an LLM judge, with scoring reports and comparison dashboards. MIT-licensed; accepts contributions of new tasks and model adapters.
- **Why it matters**: Following ReviewBench (code review) and the voice-agent three-axis evaluation, the "real-task-derived benchmark + LLM-as-judge" methodology lands in legal work — a high-expertise, high-stakes vertical — built and open-sourced by a leading company in the domain itself, giving it more authority and task realism than a third party could achieve. It also points to a general pattern: evaluating the ceiling of any professional-services agent (legal, finance, healthcare) requires a real-task benchmark with all-pass rubrics built for that specific domain — generic coding/chat benchmarks can't measure performance in the industry's deep water.
- **Category**: Evaluation
- **Related Topic**: [agent-evaluation](/en/topics/agent-evaluation)
- **Source**: https://github.com/harveyai/harvey-labs

## code-graph-rag Arrives: Cross-Language Code Understanding via a Knowledge Graph, Not Just an AST

- **Summary**: vitali87/code-graph-rag (2.7k stars total, +59/day) — parses a multi-language codebase's abstract syntax tree with Tree-sitter, then stores the result in Memgraph as a knowledge graph (rather than stopping at an AST snapshot), maintaining queryable relationships between functions, classes, imports and data flows. Supports AST-based code search and structural replacement, data-flow tracing across assignments and function calls, dead-code detection by walking call graphs, an MCP server for Claude Code and other clients, and natural-language querying via AI-generated Cypher. Supports Python, TypeScript, JavaScript, Rust, Go, Java, C/C++, C#, PHP, Lua, Dart and more.
- **Why it matters**: A graph-database implementation of "build a code structure graph for AI tools" — an interesting contrast with code-review-graph (Tree-sitter + local SQLite) from a few days earlier: same "code knowledge graph" goal, but one route is lightweight local storage plus MCP query tools, the other is a dedicated graph database plus natural-language-to-Cypher queries. The latter's advantage is native support for complex multi-hop relationship queries (e.g. "which database tables does this function's call chain ultimately touch"), at the cost of an extra graph-database dependency. The split between the two routes is itself a concrete data point on architectural choice in the emerging "code graph" sub-field.
- **Category**: Coding
- **Related Topic**: [ai-code-review](/en/topics/ai-code-review) ・ [coding-agents](/en/topics/coding-agents)
- **Source**: https://github.com/vitali87/code-graph-rag

## agency-agents Arrives: A Template of 230+ Cross-Domain Expert Personas as an Agent Team

- **Summary**: msitarzewski/agency-agents (+446/day, ~140k stars total) — a collection of 230+ specialized AI agent "personas" spanning engineering (50+ sub-specialties across frontend/backend/DevOps/security/database, etc.), design, marketing, sales, product, testing, security, game development (with Unity/Unreal/Godot specialists), GIS, finance, healthcare, academia and more across 15+ divisions. Native to Claude Code, with conversion scripts supporting Copilot, Cursor, Aider, Windsurf and 8+ other platforms; claims production-tested workflows with measurable success metrics, MIT-licensed, with both a native app and CLI install scripts.
- **Why it matters**: 140k stars shows enormous demand for the "prebuilt expert-persona team" form of skill/agent distribution — compared to a single procedural skill, it turns "swap in a whole role setup for the agent" into a ready-to-use product, and its coverage extends well beyond coding into pure business functions like marketing, sales and game development, a striking data point for the agent-capability ecosystem expanding from "engineer tooling" toward "general workplace role-play." The existence of cross-platform conversion scripts is further confirmation that skill/persona distribution is moving from single-tool-exclusive toward shared-across-tools.
- **Category**: Agent
