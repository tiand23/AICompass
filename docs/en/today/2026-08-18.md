## Community Releases 817 Cybersecurity Skills: Mapped to 6 Major Security Frameworks, Compatible With Claude Code and 20+ Platforms

- **Summary**: mukul975/Anthropic-Cybersecurity-Skills (+198 in a day, 28.5k stars total) — a community-maintained cybersecurity skill library: 817 structured skills drawn from real practitioner workflows (not generic tutorials or scripts), spanning 29 security domains (cloud security 66, threat hunting 58, threat intelligence 52, network security 43, web application security 42, digital forensics 41, malware analysis 39, identity and access management 37, and more, extending to compliance and hardware firmware security). Each skill follows a consistent structure — YAML frontmatter (for fast agent discovery) + a Markdown step-by-step workflow + reference docs + helper scripts + template assets — and is mapped to six industry frameworks: MITRE ATT&CK v19.1 (805 skills across 15 tactics, 290 techniques), NIST CSF 2.0 (804 skills covering all six functions), MITRE ATLAS 2026.07 (93 skills specifically for AI/ML adversarial threats and agentic-AI attack vectors), MITRE D3FEND v1.4.0 (139 defensive countermeasures), NIST AI RMF 1.0 (97 skills for governance functions plus GenAI risk categories), and MITRE F3 anti-fraud framework (94 skills for cyber-enabled financial fraud). To control token cost it uses progressive disclosure: scanning frontmatter alone costs ~30 tokens per skill (letting an agent search all 817 in one pass), with full content (500-2,000 tokens) loaded only for matched candidates. Natively compatible with Claude Code, GitHub Copilot, Cursor, Gemini CLI, OpenAI Codex CLI, and 20+ other platforms following the agentskills.io standard; Apache 2.0 licensed.
- **Why it matters**: This is the first time cybersecurity — a highly specialized vertical — has gotten an open-source skill collection at this scale, systematically mapped to six industry-standard frameworks rather than just MITRE ATT&CK alone. It structures cybersecurity practitioners' tacit knowledge (how to actually do threat hunting, what the steps of digital forensics are) into a knowledge layer an agent can load and execute directly. Read alongside signals this knowledge base has already logged — OpenAI's Daybreak (tiered cybersecurity model access) and reverse-skill (a pentest skill-router pack) — "agentifying cybersecurity" is now spreading comprehensively across the model layer (specialized models), the tool layer (pentest tools), and now the knowledge layer (structured skill libraries). The "lightweight frontmatter scan + load-on-match" progressive-disclosure design is also a reusable, concrete pattern for controlling context cost in large-scale skill libraries.

## ai-memory Open-Sources: A Long-Term Memory Layer for Coding Agents, With Seamless Cross-Vendor Handoff

- **Summary**: akitaonrails/ai-memory (+207 in a day, ~2.1k stars total, MIT) — a long-term memory system for coding agent CLIs, built around the scenario of "quit Claude Code mid-task, start OpenAI Codex in the same directory, continue without re-explaining the architecture." Rather than storing raw chat logs, it sanitizes session lifecycle events (prompts, tool calls, failures) and compiles them into a searchable Markdown wiki; at session end it generates a handoff summary with open questions and next steps, which the next agent receives before its first prompt as a "where you left off" briefing. Architecturally it's a single Rust binary managing one data directory (a git-versioned wiki as source of truth, immutable sanitized raw transcripts, a SQLite+FTS5 database, local embedding models, rolling logs); lifecycle hooks fire-and-forget events to a local HTTP server, which serializes writes to SQLite, compiles session pages, and serves retrieval via FTS5 full-text search, entity-match RRF, and optional vector search. It already implements hook adapters for Claude Code, Codex, Command Code, Devin, OpenCode, Cursor, and Kiro CLI — each agent's hook schema differs, but all POST observations to the same server, which is the key that makes cross-vendor handoff work. It also ships an MCP server (`memory_query`/`memory_write_page`/`memory_feedback` and other tools), a read-only web UI, and a "zero-LLM mode" that doesn't depend on any model call (falling back to FTS5 + declared entities + rule-based summaries).
- **Why it matters**: Prior memory-infrastructure discussion mostly focused on "how does the same agent/same vendor remember across sessions" — ai-memory extends the scope to "can memory travel with you when you switch to a different vendor's agent," a natural but so far rarely built next step now that using multiple coding-agent tools in parallel has become normal (holaOS reflected the same trend earlier): memory itself shouldn't be locked into a single vendor's harness. The "zero-LLM mode" design choice is also worth noting — the base retrieval/summarization capability doesn't depend on any model call at all, decoupling "having a memory system" from "being able to afford a large model," a pragmatic way to lower the adoption bar.
