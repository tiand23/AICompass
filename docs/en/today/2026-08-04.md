## Firecrawl Open-Sources pdf-inspector: The "Triage" Component for Document Parsing

- **Summary**: pdf-inspector (Rust) gained +1,699 stars in a day (8.2k total) — Firecrawl's lightweight PDF detection library: classifies a PDF as text-based/scanned/image-based/mixed in 10-50ms with confidence scores (by analyzing text vs image operators in sampled content streams), does OCR-free position-aware text extraction to clean Markdown (with table detection and multi-language encodings), runs locally in browsers via WebAssembly, and ships Python/Node bindings.
- **Why it matters**: The "first triage" of the document parsing pipeline is now a dedicated component — classify the PDF in milliseconds, then route to OCR or direct text extraction; the same trend as LlamaIndex's Parse Gateway page-level routing, at a different granularity. WASM support means triage can happen entirely on-device — sensitive documents never leave the machine.

## DeepSeek-Reasonix Hits Trending: Terminal Coding Agents Splitting Along Model Ecosystems

- **Summary**: DeepSeek-Reasonix (Go) trends for a second straight day (+883/day, 29.9k total) — a DeepSeek-native terminal coding agent: a single static Go binary with a config-driven architecture (providers/agents/tools/plugins all declared in `reasonix.toml`); context management tuned around DeepSeek's prefix cache (keeping the cache stable, pruning stale tool output) to hold down long-session costs; plugins run as stdio JSON-RPC subprocesses (MCP-compatible), and any OpenAI-compatible endpoint works as a config entry.
- **Why it matters**: Terminal coding agents are now a category of their own — and starting to split along model ecosystems: after Claude Code, here is the "DeepSeek-native" counterpart. Harness-level tuning to a specific model's cost structure (prefix cache) is a new axis of differentiation, and single-binary + config-driven represents the minimalist architectural pole of the category.
