# 2026-09-23

## Microsoft proposes an "agent-first platform" architecture: separating governance from execution

- **Summary**: Microsoft Foundry publishes a post arguing agent applications need infrastructure assumptions different from traditional apps — traditional apps respond to user requests, while agents act continuously and autonomously in loops; running agents on shared infrastructure creates security and control risks. The recommended architecture separates governance (Microsoft Foundry) from the execution environment (Azure Container Apps Sandboxes), letting agents run with scoped permissions inside hardware-isolated microVMs that are "created in seconds and gone when the work is finished" — limiting blast radius while retaining oversight. Three case studies: KPMG runs more than 30,000 Azure Container Apps Sandboxes concurrently; Cognite Atlas AI turns days-long investigations into traceable, minutes-long answers; South Australia's education system eliminated roughly 50,000 lines of custom code-interpreter state-management code.
- **Why it matters**: This systematizes the "give the agent its own computer, not a pile of tools" idea (the 08-11 monday.com Sidekick case) into an explicit infrastructure-architecture principle — separating the governance plane from the execution plane — for the first time, backed by three quantified production case studies.
