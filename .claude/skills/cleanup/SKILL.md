# /cleanup —— 全库整理

你的任务：对整个知识库做一次体检和整理。**先扫描并向用户报告发现的问题和处理方案，得到确认后再动手**（问题少而明确时可以直接做，但要在汇报里说明做了什么）。

## 检查清单（按顺序执行）

### 1. Topic 去重与合并

- 通读 `docs/topics/` 全部文件，找出：内容高度重叠的 Topic（应合并）、单薄且长期无更新的 Topic（考虑并入相近主题）。
- 合并时保留信息量大的一方为主体，被并方文件删除，全库引用改指主体，知识地图同步。

### 2. Timeline 归档

- 任何 Topic 超过约 500 行：Timeline 只留最近 3 个月，更早条目压缩成"历史演进摘要"段落放在 Timeline 小节之前。

### 3. 互链健康

- 检查所有 `[xxx](/topics/xxx)`、`[xxx](/today/xxx)` 链接指向的文件是否存在，修复或移除死链。
- 发现"应该互链而没链"的明显缺口（两个 Topic 正文互相提及却无链接）就补上。

### 4. 时效性断言复核（本 skill 独有的关键职责）

- 各 Topic 正文（简介/核心概念）里的**现状快照**会腐烂：如"X 领先""Y 已进维护模式""Z 是事实标准"。
- 逐条识别这类断言，对**距上次验证超过 3 个月**的，用 WebSearch 快速复核：仍成立 → 不动；已变化 → 更新正文并在 Timeline 记一条；无法确认 → 在断言后加"（截至 YYYY-MM）"标注。
- agent-skills 的"生态热度"排行表同样按此复核。

### 5. 三语一致性

- 中文是唯一源。抽查每个 Topic 的 en/ja 版本结构是否与中文一致（小节数、Timeline 条目数）；发现漂移的，**整篇重翻覆盖**，不做局部修补。
- 本次 cleanup 改动过的所有中文文件，其 en/ja 一律重翻。

### 6. 知识地图刷新

- 三语 map.md：核对每行的"最近动态"日期与 Topic Timeline 一致；重算状态（🔥 7 天内 / 📈 30 天内 / 💤 更久）；确认没有游离于地图之外的 Topic。

### 7. Daily 完整性

- 抽查 `docs/today/` 与 en/ja 镜像文件数量是否一致，缺译的补翻。

## 收尾

```
git add docs/ && git commit -m "cleanup: YYYY-MM 全库整理" && git push
```

汇报：合并/归档/修链/复核断言/重翻各做了几处，哪些断言发生了变化（这个用户最关心）。

## 约束

- 不新增 Topic（那是 /update 和 /topic 的职责），只整理已有的。
- 不输出推荐指数。
- 拿不准要不要合并的，倾向保守——列出来问用户，误合并比重复更难恢复。
